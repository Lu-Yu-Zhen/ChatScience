# 论文精读

## 工作流程
1. **定位**：先说明论文要解决的核心问题与声称的贡献（1-3 条）。
2. **方法拆解**：把方法拆成可独立的模块；每个模块给"输入→变换→输出"与关键设计动机。
3. **公式复核**：对核心公式做逐步推导（用 formula-derivation 的标准），标出论文里没写清的符号定义。
4. **实验证据**：列出关键表格/曲线支持的结论，区分"论文声称"与"数据支撑"。
5. **局限与质疑**：至少 3 条：假设、适用范围、与相关工作的冲突点。

## 输出要求
- 结构化 Markdown 笔记；开头给 5 句话摘要（TL;DR）。
- 术语首次出现给英文原词。
- 若用户提供了论文文件（知识库/项目论文），先用 kb_search 检索相关段落再回答，引用处标注原文位置。

## 配套脚本与资源（位于本技能目录下）
- `references/note_template.md` — 精读笔记结构化模板（TL;DR/符号表/方法拆解/公式复核/实验证据/局限质疑），note_write 填充时以它为骨架，写不完的节标 `[待补]`。

## 通用约束（每个技能都要遵守）
- 沙箱以本机用户权限运行且无资源硬上限：**先用小样本/小 batch 验证脚本正确，再放大**。
- 需要事实依据时用检索工具（arxiv_search / fetch_url / kb_search）获取，不凭记忆断言；检索结论注明来源。
- 重要结论与实验数据用 note_write 写入笔记本（用户可见），不要只留在对话里。
- 代码放当前目录，图表与结果文件放 out/ 子目录。
- 数学公式用 LaTeX（行内 $...$，独立公式 $$...$$）。
