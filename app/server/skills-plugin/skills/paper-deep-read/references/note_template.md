# 精读笔记模板（note_write 直接填充本结构）

> 使用说明：复制以下骨架到 note_write 的 content 参数，逐节填充；写不完的节
> 标注 `[待补]`，不要留空节。`〈〉` 为占位符。

```markdown
# 精读：〈论文标题〉（〈arXiv id / venue 年份〉）

## TL;DR（5 句话）
1. 〈问题：这篇论文要解决什么〉
2. 〈声称：核心贡献一句话〉
3. 〈方法：关键机制一句话〉
4. 〈证据：最强的一条实验支持〉
5. 〈局限：最大的疑问〉

## 符号表
| 符号 | 含义 | 维度/取值域 | 首现位置 |

## 1. 问题定义
- 输入 / 输出形式化：
- 与已有问题的区别（不是 incremental 的点在哪）：

## 2. 方法拆解（每模块：输入 → 变换 → 输出 + 设计动机）
### 2.1 〈模块名〉
- 公式（LaTeX）：
- 动机（为什么不这样做不行）：
- 论文没写清的细节：〈列出并标注 [可推断]/[需假设]〉

## 3. 公式复核（对核心公式逐步推导，标注每步依据）
〈推导；用 grad_check 脚本数值验证的写上验证结果〉

## 4. 实验证据
| 声称 | 支撑数据（表/图/step 区间） | 属于"论文声称"还是"数据可复核" |

## 5. 局限与质疑（至少 3 条）
1. 〈假设层面的〉
2. 〈适用范围层面的〉
3. 〈与相关工作冲突的〉

## 引用与定位
- arXiv id / 链接：
- 本地知识库检索位置（kb_search 命中段落）：〈如有〉
```

## 填写纪律
- 术语首次出现给英文原词，如 自注意力（self-attention）。
- "论文声称"与"你核实过的"两栏绝不混写；未核实的保留声称字样。
- 结论性句子必须能在上文找到对应模块编号，方便回溯。
