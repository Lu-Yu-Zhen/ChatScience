# 科研问题分解

## 流程
1. 复述任务目标，指出其中的模糊点与隐含假设；与用户确认（或列出所采用的解释）。
2. 自顶向下拆解：总目标 → 子问题（2-4 层），每个子问题写成「可以独立回答/验证」的形式。
3. 标注依赖关系：哪些子问题必须先完成、哪些可以并行。
4. 每个子问题给出：验证标准（怎样算完成）、需要的信息/工具、预估成本（高/中/低）。
5. 排序输出执行顺序，标出关键路径与最可能阻塞的环节。

## 输出要求
- 用树/表格呈现：编号 / 子问题 / 依赖 / 验证标准 / 所需工具 / 成本。
- 子问题的粒度以「一次工具调用或一轮检索能推进」为准，不拆成空话。
- 明确写出「本任务不需要做什么」（防范围蔓延）。
- 拆解结果用 note_write 记录，供后续环节引用。

## 通用约束（每个技能都要遵守）
- 沙箱以本机用户权限运行且无资源硬上限：**先用小样本/小 batch 验证脚本正确，再放大**。
- 需要事实依据时用检索工具（arxiv_search / fetch_url / kb_search）获取，不凭记忆断言；检索结论注明来源。
- 重要结论与实验数据用 note_write 写入笔记本（用户可见），不要只留在对话里。
- 代码放当前目录，图表与结果文件放 out/ 子目录。
- 数学公式用 LaTeX（行内 $...$，独立公式 $$...$$）。
