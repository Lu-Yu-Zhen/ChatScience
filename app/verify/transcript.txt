Q: DeepSeek-V4 的训练目标（预训练目标）是什么？与上一代相比主要改进了什么？
A: 基于论文全文，DeepSeek-V4 的**预训练目标本身并不是一个全新的损失函数**，而是延续了 DeepSeek-V3 的核心预训练范式：**标准语言建模目标 + Multi-Token Prediction 辅助目标**。与上一代相比，主要改进集中在**架构、优化器、数据构造、长上下文训练策略和基础设施**上，从而在支持 1M token 上下文的同时显著降低推理计算量和 KV cache 开销。

## 一、DeepSeek-V4 的预训练目标

### 1. 主目标：标准自回归语言建模损失

论文 Figure 2 的整体架构中明确包含：

- **LM Loss**：语言建模损失，即对下一个 token 的预测损失；
- **MTP Loss**：Multi-Token Prediction 辅助损失。

也就是说，DeepSeek-V4 的预训练主目标仍然是让模型根据已有上下文预测后续 token。

---

### 2. 辅助目标：Multi-Token Prediction，MTP

论文第 2.1 节指出：

> “Given that the MTP strategy has been validated in DeepSeek-V3, we adopt the same strategy for DeepSeek-V4 series without modification.”

即 DeepSeek-V4 沿用了 DeepSeek-V3 的 **Multi-Token Prediction** 策略，没有修改其基本形式。

在第 4.2.2 节的训练设置中，论文进一步说明 MTP 损失权重：

- 大部分训练阶段：MTP loss weight = **0.3**
- 学习率衰减开始后：MTP loss weight = **0.1**

因此，DeepSeek-V4 的预训练目标可以概括为：

\[
\mathcal{L}_{\text{pretrain}}
=
\mathcal{L}_{\text{LM}}
+
\lambda_{\text{MTP}} \mathcal{L}_{\text{MTP}}
\]

其中论文没有给出显式公式，但 Figure 2 和 4.2.2 明确存在 LM Loss 与 MTP Loss，且 MTP 权重随训练阶段调整。

---

### 3. MoE 负载均衡相关目标

论文第 2.1 节说明 DeepSeek-V4 仍使用 DeepSeekMoE，并采用：

- **auxiliary-loss-free load balancing strategy**：无辅助损失的负载均衡策略；
- 同时加入一个轻微的 **sequence-wise balance loss**，用于防止单个序列内部出现极端不均衡。

第 4.2.2 节给出该 balance loss 的权重为：

- balance loss weight = **0.0001**

这可以视为预训练过程中的正则化/辅助优化目标，但不是主要语言建模目标。

---

### 4. 数据与预训练规模

论文摘要和第 4.2.2 节说明：

- DeepSeek-V4-Flash：预训练 **32T tokens**
- DeepSeek-V4-Pro：预训练 **33T tokens**
- 两者均支持 **1,000,000 token** 上下文

第 4.1 节还提到一个重要训练细节：

> “Different from DeepSeek-V3, we employ sample-level attention masking during pre-training.”

即在预训练中采用样本级 attention mask。这有助于在 packed sequence 中避免不同文档/样本之间产生错误注意力，提高长上下文训练质量。

## 二、与上一代相比主要改进了什么？

这里的“上一代”需要区分：

- **DeepSeek-V3**：架构继承与改进的参照对象；
- **DeepSeek-V3.2**：效率与部分能力比较的参照对象。

论文主要围绕以下方面进行改进。

---

# 1. 架构改进：引入 Hybrid Attention，大幅降低长上下文成本

这是 DeepSeek-V4 最核心的改进。

论文第 1 节和第 2.3 节指出，DeepSeek-V4 引入了两种高效注意力机制：

1. **Compressed Sparse Attention, CSA**
2. **Heavily Compressed Attention, HCA**

并采用两者交替的 hybrid attention 架构。

---

## 1.1 CSA：压缩 + 稀疏注意力

CSA 的核心思想是：

1. 先压缩 KV cache；
2. 再使用 DeepSeek Sparse Attention, DSA 选择 top-k 压缩后的 KV entries；
3. 同时加入 sliding window KV entries 以保留局部细粒度依赖。

论文第 2.3.1 节说明：

> “CSA compresses the KV cache along the sequence dimension and then performs DeepSeek Sparse Attention.”

在 DeepSeek-V4-Flash 和 DeepSeek-V4-Pro 中，CSA 的压缩率设置为：

\[
m = 4
\]

也就是说，每 4 个 token 的 KV entries 被压缩为一个 entry。

---

## 1.2 HCA：更重压缩，但保持 dense attention

HCA 的目标是进一步压缩 KV cache，但不使用稀疏选择。

论文第 2.3.2 节说明：

> “HCA applies more aggressive compression to the KV caches but keeps dense attention.”

在 DeepSeek-V4 中，HCA 的压缩率设置为：

\[
m' = 128
\]

即每 128 个 token 的 KV entries 被压缩为一个 entry。

---

## 1.3 与 DeepSeek-V3.2 相比的效率提升

论文摘要和 Figure 1 给出了非常关键的结果：

在 **1M token 上下文**下：

### DeepSeek-V4-Pro 相比 DeepSeek-V3.2

- 单 token 推理 FLOPs：仅为 DeepSeek-V3.2 的 **27%**
- KV cache：仅为 DeepSeek-V3.2 的 **10%**

### DeepSeek-V4-Flash 相比 DeepSeek-V3.2

- 单 token 推理 FLOPs：仅为 DeepSeek-V3.2 的 **10%**
- KV cache：仅为 DeepSeek-V3.2 的 **7%**

论文第 2.3.4 节还指出，如果以 BF16 GQA8、head dimension 128 作为常见基线，DeepSeek-V4 在 1M 上下文下的 KV cache 大小可降至该基线的约 **2%**。

---

# 2. 残差连接改进：引入 Manifold-Constrained Hyper-Connections, mHC

论文第 2.2 节指出，DeepSeek-V4 引入 **Manifold-Constrained Hyper-Connections, mHC** 来增强传统残差连接。

标准 Hyper-Connections 的残差状态更新为：

\[
X_{l+1} = B_l X_l + C_l F_l(A_l X_l)
\]

其中：

- \(A_l\)：输入映射；
- \(B_l\)：残差变换；
- \(C_l\)：输出映射；
- \(F_l\)：第 \(l\) 层模块，例如 MoE 层。

mHC 的关键创新是将残差映射矩阵 \(B_l\) 约束到 **doubly stochastic matrices** 流形上：

\[
B_l \in \mathcal{M}
=
\left\{
M \in \mathbb{R}^{n \times n}
\mid
M \mathbf{1}_n = \mathbf{1}_n,
\mathbf{1}_n^T M = \mathbf{1}_n^T,
M \ge 0
\right\}
\]

论文解释这样做的意义：

1. 保证残差映射的谱范数不超过 1；
2. 使残差变换是非扩张的；
3. 提高前向和反向传播中的数值稳定性；
4. 在深层堆叠时仍保持稳定。

在 DeepSeek-V4 中，mHC 的配置为：

- expansion factor：\(n_{\text{hc}} = 4\)
- Sinkhorn-Knopp 迭代次数：\(t_{\max} = 20\)

---

# 3. 优化器改进：引入 Muon optimizer

论文第 2.4 节指出，DeepSeek-V4 在大多数模块中使用 **Muon optimizer**，以获得：

- 更快收敛；
- 更高训练稳定性。

但并非所有参数都用 Muon。论文说明以下模块仍使用 AdamW：

- embedding module；
- prediction head module；
- mHC 的 static biases 和 gating factors；
- 所有 RMSNorm 模块权重。

Muon 的核心步骤包括：

1. 计算梯度；
2. 累积 momentum；
3. 使用 hybrid Newton-Schulz iterations 对更新矩阵进行正交化；
4. rescale update RMS；
5. 执行 weight decay 和参数更新。

论文第 2.4 节给出 Newton-Schulz iteration 的形式：

\[
M_k =
a M_{k-1}
+
b (M_{k-1} M_{k-1}^T) M_{k-1}
+
c (M_{k-1} M_{k-1}^T)^2 M_{k-1}
\]

DeepSeek-V4 使用 10 步 hybrid Newton-Schulz：

- 前 8 步：\((a,b,c) = (3.4445, -4.7750, 2.0315)\)
- 后 2 步：\((a,b,c) = (2, -1.5, 0.5)\)

---

# 4. MoE 设计改进：保留 DeepSeekMoE，但做关键调整

论文第 2.1 节说明，DeepSeek-V4 仍采用 DeepSeekMoE，但相比 DeepSeek-V3 有几个重要变化。

### 4.1 激活函数变化

MoE affinity score 的激活函数从：

\[
\text{Sigmoid}(\cdot)
\]

改为：

\[
\text{Sqrt}(\text{Softplus}(\cdot))
\]

---

### 4.2 负载均衡变化

保留 auxiliary-loss-free load balancing，但增加轻微的 sequence-wise balance loss，防止单个序列内部出现极端不均衡。

---

### 4.3 移除 routing target node 数量限制

论文说明：

> “For DeepSeek-V4, we remove the constraint on the number of routing target nodes.”

---

### 4.4 初始 dense FFN 层改为 Hash-routed MoE 层

相比 DeepSeek-V3，DeepSeek-V4 将初始若干 Transformer block 中的 dense FFN 替换为使用 **Hash routing** 的 MoE 层。

在第 4.2.1 节模型设置中，论文说明：

- DeepSeek-V4-Flash：前 3 个 MoE 层使用 Hash routing；
- DeepSeek-V4-Pro：前 3 个 MoE 层使用 Hash routing。

---

# 6. 训练稳定性改进

论文第 4.2.3 节指出，训练万亿参数 MoE 模型时存在 loss spike 问题，DeepSeek-V4 提出两个实用技术：

## 6.1 Anticipatory Routing

核心思想是解耦 backbone 网络与 routing 网络的同步更新。

在第 \(t\) 步：

- 特征计算使用当前参数 \(\theta_t\)；
- routing indices 使用历史参数 \(\theta_{t-\Delta t}\) 计算并提前缓存。

论文说明该机制可显著缓解 loss spike，并且通过基础设施优化，额外 wall-clock time overhead 约 **20%**。

---

## 6.2 SwiGLU Clamping

在 SwiGLU 中对数值范围进行 clamp：

- linear component clamp 到：

\[
[-10, 10]
\]

- gate component upper bound capped at：

\[
10
\]

论文称这能有效消除 outlier，并稳定训练，同时不损害性能。

---

# 7. 基础设施与系统优化

论文第 3 节说明 DeepSeek-V4 的训练和推理框架也有大量改进。

### 7.1 MoE 通信计算重叠

第 3.1 节提出 fine-grained Expert Parallelism scheme，将 MoE 中的通信和计算融合到一个 pipelined kernel 中。

论文报告：

- 相比非融合基线，一般推理负载加速 **1.50～1.73×**
- 在 RL rollout、高速 agent serving 等延迟敏感场景最高加速 **1.96×**

---

### 7.2 TileLang kernel 开发

第 3.2 节说明使用 TileLang DSL 开发 fused kernels，减少大量细粒度 Torch ATen operator 调用，并降低 host-side overhead。

---

### 7.3 batch-invariant 与 deterministic kernels

第 3.3 节说明 DeepSeek-V4 实现了端到端 bitwise batch-invariant 和 deterministic kernels，用于：

- 调试；
- 稳定性分析；
- 预训练、后训练、推理之间的一致性。

---

### 7.4 长上下文 Contextual Parallelism

第 3.4.3 节说明针对 CSA/HCA 的压缩注意力设计了 two-stage contextual parallelism，以解决压缩边界和不同 rank 上 compressed KV 长度不一致的问题。

---

### 7.5 异构 KV cache 与磁盘 KV cache

第 3.5 节说明 DeepSeek-V4 设计了 heterogeneous KV cache structure，用于管理 CSA、HCA、SWA 等不同类型 KV entries，并支持 on-disk KV cache storage 来复用 shared prefix。

Q: 请用 LaTeX 格式给出论文中一个关键公式（用 $$ 包裹），并解释每个符号的含义。
A: 可以给出论文第 2.2 节中关于 **Manifold-Constrained Hyper-Connections, mHC** 的关键公式：

$$
B_l \in \mathcal{M} \coloneqq \left\{ M \in \mathbb{R}^{n \times n} \mid M \mathbf{1}_n = \mathbf{1}_n,\; \mathbf{1}_n^T M = \mathbf{1}_n^T,\; M \ge 0 \right\}
$$

其中各符号含义如下：

- \(B_l\)：第 \(l\) 层 Transformer 中的**残差变换矩阵**。在 Hyper-Connections 中，它负责混合上一层的残差状态。
- \(\mathcal{M}\)：一个**流形约束集合**，论文中具体是**双随机矩阵流形**，也称为 Birkhoff polytope。
- \(M\)：属于该流形的任意一个矩阵，用来表示满足约束的残差映射。
- \(\mathbb{R}^{n \times n}\)：\(n \times n\) 的实数矩阵空间。这里的 \(n\) 对应残差流的扩展宽度，论文中记为 \(n_{\mathrm{hc}}\)。
- \(\mathbf{1}_n\)：长度为 \(n\) 的全 1 向量。
- \(M \mathbf{1}_n = \mathbf{1}_n\)：表示矩阵 \(M\) 的**每一行元素之和等于 1**。
- \(\mathbf{1}_n^T M = \mathbf{1}_n^T\)：表示矩阵 \(M\) 的**每一列元素之和等于 1**。
- \(M \ge 0\)：表示矩阵 \(M\) 的**所有元素都非负**。

这个公式的核心意义是：DeepSeek-V4 没有让残差变换矩阵 \(B_l\) 完全自由学习，而是把它约束到**双随机矩阵流形**上。论文指出，这样做可以保证残差映射的谱范数不超过 1，使残差变换具有“非扩张”性质，从而增强深层 Transformer 中信号传播的稳定性。

Q: 请给出一段 Python 代码示例，展示如何用伪代码描述论文中的训练流程（用 ``` 代码块）。
A: 下面给出一段 **Python 伪代码**，用于概括论文中 DeepSeek-V4 的主要训练流程。它不是论文官方代码，而是根据论文第 2.1、2.4、4.2、4.2.3、5.1、5.2 节内容整理出的流程化伪代码。

```python
# ============================================================
# DeepSeek-V4 训练流程伪代码
# 依据论文内容整理：
# - 预训练：LM Loss + MTP Loss + MoE balance loss
# - 优化器：Muon 为主，AdamW 用于部分模块
# - 长上下文训练：4K -> 16K -> 64K -> 1M
# - 稀疏注意力：先 dense warm-up，再引入 CSA/HCA sparse attention
# - 稳定性：Anticipatory Routing + SwiGLU Clamping
# - 后训练：Specialist SFT + GRPO RL + On-Policy Distillation
# ============================================================


class DeepSeekV4Trainer:
    def __init__(self, model, tokenizer, optimizer_muon, optimizer_adamw,
                 config):
        self.model = model
        self.tokenizer = tokenizer
        self.optimizer_muon = optimizer_muon
        self.optimizer_adamw = optimizer_adamw
        self.config = config

        # 论文第 4.2.2 节：训练序列长度逐步扩展
        self.seq_length_schedule = [4096, 16384, 65536, 1_000_000]

        # 论文第 4.2.2 节：MTP loss weight
        # 大部分阶段为 0.3，学习率衰减后为 0.1
        self.mtp_loss_weight_normal = 0.3
        self.mtp_loss_weight_decay = 0.1

        # 论文第 2.1 / 4.2.2 节：MoE sequence-wise balance loss weight
        self.balance_loss_weight = 0.0001

        # 论文第 4.2.3 节：SwiGLU clamping
        self.swiglu_linear_clamp = (-10.0, 10.0)
        self.swiglu_gate_upper_bound = 10.0

        # 论文第 4.2.3 节：Anticipatory Routing
        # routing indices 使用历史参数 theta_{t - delta_t} 提前计算
        self.anticipatory_routing_delta_t = 1
        self.cached_routing_indices = None

    # ------------------------------------------------------------
    # 1. 预训练单步：forward + loss + optimizer update
    # ------------------------------------------------------------
    def pretrain_step(self, batch, global_step, lr_schedule_state):
        input_ids = batch["input_ids"]
        attention_mask = batch["attention_mask"]

        # 论文第 4.1 节：
        # DeepSeek-V4 与 DeepSeek-V3 不同，预训练使用 sample-level attention masking
        attention_mask = build_sample_level_attention_mask(
            packed_sequence=input_ids,
            sample_boundaries=batch["sample_boundaries"],
        )

        # 论文第 4.2.2 节：
        # 前 1T tokens 使用 dense attention warm-up；
        # 在 64K 序列长度阶段引入 sparse attention。
        use_sparse_attention = should_use_sparse_attention(
            global_step=global_step,
            current_seq_length=self.current_seq_length(global_step),
            dense_warmup_tokens=1e12,
            sparse_start_seq_length=65536,
        )

        # 论文第 4.2.3 节：
        # Anticipatory Routing：
        # 特征计算使用当前参数 theta_t，
        # routing indices 使用历史参数 theta_{t-delta_t} 计算并缓存。
        if self.anticipatory_routing_enabled():
            routing_indices = self.get_or_compute_anticipated_routing_indices(
                input_ids=input_ids,
                historical_params=self.model.params_at_step(global_step - self.anticipatory_routing_delta_t),
            )
        else:
            routing_indices = None

        # 前向传播：
        # 包含 CSA / HCA hybrid attention、DeepSeekMoE、MTP modules
        outputs = self.model.forward(
            input_ids=input_ids,
            attention_mask=attention_mask,
            use_sparse_attention=use_sparse_attention,
            routing_indices=routing_indices,
            swiglu_linear_clamp=self.swiglu_linear_clamp,
            swiglu_gate_upper_bound=self.swiglu_gate_upper_bound,
        )

        # 论文 Figure 2：预训练目标包含 LM Loss 和 MTP Loss
        lm_loss = compute_language_modeling_loss(
            logits=outputs.next_token_logits,
            labels=input_ids,
        )

        mtp_loss = compute_multi_token_prediction_loss(
            logits=outputs.mtp_logits,
            labels=outputs.mtp_labels,
        )

        # 论文第 2.1 / 4.2.2 节：
        # auxiliary-loss-free load balancing + sequence-wise balance loss
        moe_balance_loss = compute_sequence_wise_balance_loss(
            expert_loads=outputs.moe_expert_loads,
        )

        mtp_weight = (
            self.mtp_loss_weight_decay
            if lr_schedule_state["learning_rate_decaying"]
            else self.mtp_loss_weight_normal
        )

        total_loss = (
            lm_loss
            + mtp_weight * mtp_loss
            + self.balance_loss_weight * moe_balance_loss
        )

        total_loss.backward()

        # 论文第 2.4 节：
        # 大部分模块使用 Muon optimizer；
        # embedding、prediction head、RMSNorm、mHC static biases/gating factors 使用 AdamW。
        self.optimizer_muon.step()
        self.optimizer_adamw.step()

        self.optimizer_muon.zero_grad()
        self.optimizer_adamw.zero_grad()

        return total_loss

    # ------------------------------------------------------------
    # 2. Muon optimizer 单步更新
    # 对应论文 Algorithm 1
    # ------------------------------------------------------------
    def muon_update(self, W, grad, momentum_buffer, lr, momentum,
                    weight_decay, rescale_factor):
        # G_t = ∇_W L_t(W_{t-1})
        G_t = grad

        # M_t = μ M_{t-1} + G_t
        momentum_buffer = momentum * momentum_buffer + G_t

        # O'_t = HybridNewtonSchulz(μ M_t + G_t)
        # 论文第 2.4 节：
        # 前 8 步使用快速收敛系数，后 2 步使用稳定系数
        O_t_prime = hybrid_newton_schulz(
            matrix=momentum * momentum_buffer + G_t,
            num_iterations=10,
            early_coefficients=(3.4445, -4.7750, 2.0315),
            final_coefficients=(2.0, -1.5, 0.5),
        )

        # O_t = O'_t * sqrt(max(n, m)) * γ
        n, m = W.shape
        O_t = O_t_prime * (max(n, m) ** 0.5) * rescale_factor

        # W_t = W_{t-1} * (1 - ηλ) - η O_t
        W = W * (1 - lr * weight_decay) - lr * O_t

        return W, momentum_buffer

    # ------------------------------------------------------------
    # 3. 后训练：Specialist Training
    # 论文第 5.1.1 节：
    # 对数学、代码、agent、instruction following 等领域分别训练专家模型
    # ------------------------------------------------------------
    def train_specialist(self, domain_name, sft_dataset, rl_dataset):
        specialist_model = self.model.copy()

        # 第一阶段：Supervised Fine-Tuning
        # 论文第 5.1.1 节：
        # base model 先在高质量领域数据上 SFT，建立基础能力
        specialist_model = supervised_fine_tune(
            model=specialist_model,
            dataset=sft_dataset,
            domain=domain_name,
        )

        # 第二阶段：Reinforcement Learning with GRPO
        # 论文第 5.1.1 节：
        # 使用 Group Relative Policy Optimization 进行领域强化
        specialist_model = grpo_reinforcement_learning(
            model=specialist_model,
            dataset=rl_dataset,
            reward_model_or_verifier=domain_specific_reward(domain_name),
            reasoning_mode="think_max",  # 论文 Table 2/3：不同 reasoning effort
        )

        return specialist_model

    # ------------------------------------------------------------
    # 4. 后训练：On-Policy Distillation
    # 论文第 5.1.2 节：
    # 多个领域专家作为 teacher，统一 student 通过 reverse KL 合并能力
    # ------------------------------------------------------------
    def on_policy_distillation(self, student_model, teacher_models,
                               training_dataset, num_steps):
        """
        论文式 (29)：
            L_OPD(θ) = Σ_i w_i * D_KL(π_θ || π_E_i)

        其中：
        - π_θ：student policy
        - π_E_i：第 i 个 domain expert teacher
        - w_i：teacher 权重
        - D_KL：reverse KL，即 KL(student || teacher)
        """
        student = student_model

        for step in range(num_steps):
            batch = next_batch(training_dataset)

            # 论文第 5.1.2 节：
            # 从 student 自身采样 trajectory，保持 on-policy
            student_trajectories = rollout_student(
                model=student,
                prompts=batch["prompts"],
                context_window=batch["context_window"],
            )

            total_opd_loss = 0.0

            for teacher_idx, teacher in enumerate(teacher_models):
                teacher_weight = get_teacher_weight(teacher_idx)

                # 论文第 5.2.2 节：
                # 使用 full-vocabulary logits distillation，
                # 而不是 token-level KL estimate，以降低梯度方差
                student_logits = forward_logits(student, student_trajectories)
                teacher_logits = forward_logits(teacher, student_trajectories)

                # 论文式 (29)：
                # w_i * D_KL(π_θ || π_E_i)
                kl_term = reverse_kl_full_vocabulary(
                    student_logits=student_logits,
                    teacher_logits=teacher_logits,
                )

                total_opd_loss += teacher_weight * kl_term

            total_opd_loss.backward()
            optimizer_step(student)

        return student

    # ------------------------------------------------------------
    # 5. 后训练中的 FP4 Quantization-Aware Training
    # 论文第 5.2.1 节：
    # 对 MoE expert weights 和 CSA indexer QK path 做 FP4 QAT
    # ------------------------------------------------------------
    def fp4_qat_step(self, model, batch):
        """
        论文第 5.2.1 节：
        - FP32 master weights -> FP4 -> FP8 computation
        - FP4-to-FP8 dequantization 在满足 scale 条件时是 lossless
        - backward 中通过 STE 将梯度传回 FP32 master weights
        """
        for module in model.modules():
            if is_moe_expert_weight(module) or is_csa_indexer_qk_path(module):
                # 论文：FP32 master weights quantized to FP4
                fp4_weights = quantize_to_fp4(module.fp32_master_weights)

                # 论文：dequantized back to FP8 for computation
                fp8_weights = dequantize_fp4_to_fp8(fp4_weights)

                # 论文：FP4-to-FP8 dequantization is lossless
                assert fp8_weights_is_lossless(fp4_weights, fp8_weights)

                # 前向使用模拟 FP4/FP8 行为
                output = module.forward_with_fp8_weights(
                    fp8_weights=fp8_weights,
                    inputs=batch["hidden_states"],
                )

                # 论文：gradients propagated back to FP32 master weights
                # equivalent to Straight-Through Estimator (STE)
                gradient = output.backward_ste_through_fp4()

                module.fp32_master_weights.apply_adam_or_muon_update(gradient)

        return model
```

这段伪代码概括了论文中的主要训练流程：

1. **预训练阶段**：使用语言建模损失、Multi-Token Prediction 损失和 MoE 序列级负载均衡损失。  
2. **优化器设置**：大部分参数使用 Muon optimizer，embedding、prediction head、RMSNorm、mHC static biases/gating factors 等使用 AdamW。  
3. **长上下文训练**：序列长度从 4K 扩展到 16K、64K，再到 1M；先 dense attention warm-up，再引入 CSA/HCA sparse attention。  
4. **训练稳定性**：使用 Anticipatory Routing 和 SwiGLU Clamping 缓解 loss spike。  
5. **后训练阶段**：先训练领域专家，再通过 On-Policy Distillation 合并多个专家能力。  
6. **量化训练**：后训练中加入 FP4 Quantization-Aware Training，用于 MoE expert weights 和 CSA indexer QK path。

---

## 一、论文明确承认的局限

### 1. 架构设计较为复杂

论文指出，DeepSeek-V4 为了追求极致的长上下文效率，采用了比较“大胆”的架构设计。但为了降低风险，模型保留了许多此前初步验证过的组件和技巧。

这些设计虽然有效，但代价是架构相对复杂。论文原文大意是：

> 为最小化风险，我们保留了许多初步验证过的组件和技巧，这些设计虽然有效，但使架构相对复杂。

因此，论文将“简化架构”列为未来方向：

> 未来迭代中，将进行更全面、更有原则性的研究，把架构蒸馏到最本质的设计，使其更优雅，同时不牺牲性能。

对应论文：**Section 6**。

---

### 2. 训练稳定性技巧的理论解释不足

论文在预训练中提出了两个缓解 loss spike 的技术：

1. **Anticipatory Routing**
2. **SwiGLU Clamping**

这两个方法在实践中有效，但论文明确承认它们的底层机制尚不清晰：

> 尽管 Anticipatory Routing 和 SwiGLU Clamping 已被证明能有效缓解训练不稳定，但它们背后的原理仍缺乏充分理解。

因此，未来方向是：

- 研究大规模训练稳定性的基础问题；
- 加强内部指标监测；
- 建立更原则性、可预测的稳定训练方法。

对应论文：**Section 4.2.3** 与 **Section 6**。

---

### 3. 与最强闭源模型仍有差距

虽然论文称 DeepSeek-V4-Pro-Max 重新定义了开放模型 SOTA，但在多个高难任务上仍落后于前沿闭源模型。

例如：

#### 知识任务

在 SimpleQA-Verified 上：

- DeepSeek-V4-Pro-Max：**57.9**
- Gemini-3.1-Pro：**75.6**

差距仍较明显。

#### 推理任务

论文在引言中总结：

> DeepSeek-V4-Pro-Max 的表现略低于 GPT-5.4 和 Gemini-3.1-Pro，说明其发展轨迹大约落后前沿闭源模型 3 到 6 个月。

对应论文：**Section 1**、**Section 5.3.2**。

---

### 4. 长上下文性能在超过一定长度后仍有退化

论文强调 DeepSeek-V4 支持 1M token 上下文，并显著降低 KV cache 与 FLOPs。但在长上下文检索评测中，性能并非完全无损。

Figure 9 对应的讨论指出：

- 在 **128K 以内**，DeepSeek-V4-Pro-Max 的检索性能非常稳定；
- 超过约 **128K** 后，性能开始出现可见下降；
- 不过在 **1M token** 下，相比多数闭源和开源模型仍然保持较强能力。

这说明其百万 token 上下文能力很强，但长距离检索仍存在一定退化。

对应论文：**Section 5.3.2**，Figure 9。

### 5. DeepSeek-V4-Flash 在知识与复杂 Agent 任务上弱于 Pro

论文在引言中比较了 Pro 与 Flash：

- Flash 由于参数规模较小，在知识评测中表现低于 Pro；
- 在推理任务上，如果给 Flash 更大的 thinking budget，可以达到接近 Pro 的结果；
- 但在更复杂、高难度的 Agent 任务上，Flash 仍然落后于 Pro。

- DeepSeek-V4-Pro-Max：**67.9**
- DeepSeek-V4-Flash-Max：**56.9**

## 五、总结

如果用最简短的方式概括，这篇论文的局限和未来方向主要有：

1. **架构复杂**：为了效率保留了很多组件，未来需要更简洁、更有原则的设计。  
2. **训练稳定性机制尚不完全清楚**：Anticipatory Routing 和 SwiGLU Clamping 有效，但理论解释不足。  
3. **与最强闭源模型仍有差距**：尤其在高难知识、复杂推理和部分 Agent 任务上。  
4. **长上下文并非完全无损**：超过约 128K 后检索性能开始下降。  
5. **Flash 在知识和复杂任务上弱于 Pro**：参数规模更小带来能力限制。  
6. **真实任务中仍有格式、指令遵循、低级错误和过度思考问题**。  
7. **未来方向包括架构简化、训练稳定性理论、更稀疏 embedding、低延迟部署、长程 Agent、多模态和更强数据策略**。
