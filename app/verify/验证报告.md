### 架构决策说明（实事求是）
- 前端**未迁移 React/Vue**：现有单文件前端是经多轮验收打磨的成熟 UI 资产，重写风险远大于收益。Electron 直接承载该前端 + Node/Express 后端实现前后端分离，满足"独立前端界面与后端服务"的核心目标。React/Vue 迁移可作为后续迭代。
- TLS 1.3 说明：对外调用（阿里云百炼）由 Node 默认启用 TLS 1.2/1.3 加密传输；本机环回（渲染层↔后端）不启用 TLS，而采用**随机 24 字节 token 鉴权 + 仅绑定 127.0.0.1 + contextIsolation/sandbox + IPC 白名单**的纵深防御（环回 TLS 无实际威胁模型支撑，属于过度设计）。
- 同步延迟：交互类操作（通知/置顶/窗口）走 IPC 即时（<10ms）；状态持久化采用 **180ms 差量检测**（<200ms 阈值）+ 原子写入（tmp+rename）。

| 技能 | SDK local plugin（`app/server/skills-plugin` 播种 → `app/data/skills-plugin`），`skills` 数组白名单 |
| 多轮 | SDK 原生 `resume`（conv.sdkSessionId 持久化），不手工拼历史 |
| 模型 | SDK 五档（auto/ultimate/performance/efficient/lite），与 Chat 模式的厂商模型体系独立 |

# 追加轮 2：下拉隐形根因 + 全局悬浮滚动条（build 09-06 09:24）

用户复报「Agent 下拉点击无响应」并要求「所有滚动条变细、鼠标移入区域才显示」。本轮在**真实打包窗口**（computer-use 真实鼠标点击 + CDP 主世界断言）完成定位与验证：

## 1. 下拉「无响应」真正根因：隐形菜单（opacity:0 + pointer-events:none）

`#agentSelectMenu` 挂了 `class="dropdown-menu"`，该类的 CSS 是**配合父级 `.open` 类**的显隐方案（`.dropdown-menu { opacity:0; transform:…; pointer-events:none }`，只有 `.model-select.open / .settings-wrap.open` 的后代才解除）。而智能体按钮的 JS 只切 `menu.style.display`，父级从不挂 `.open`——于是菜单「打开」后**透明且不可点**，肉眼看就是「点了没反应」。上一轮加的空列表兜底只治了「列表未就绪」，没治这个，所以用户仍复现。

- 修复：`#agentSelectMenu { opacity:1; transform:none; pointer-events:auto; }`（ID 特异性覆盖类规则，菜单随 display 立即显隐）。
- 教训：**DOM 断言（display:block、children 数）证明不了视觉可见**——本轮在真实窗口用 elementFromPoint/计算样式才抓到。

## 2. 全局滚动条：6px 细条 + 指针移入才显现

- 全局规则：`::-webkit-scrollbar{width/height:6px}`、thumb 默认 `transparent`、`*:hover::-webkit-scrollbar-thumb` 才显色（悬停其所在滚动区域即显现），thumb:hover 加深；track/corner 透明。
- 移除了会**禁用 ::-webkit-scrollbar 定制**的 `scrollbar-width: thin/none` 声明（Chromium 130 中二者互斥）：`#sidebarScroll` 行内 thin、`.chat-scroll` 的 thin+scrollbar-color、`#ctxChips` 行内 none。聊天主区滚动条仍按原设计隐藏（右侧消息导航条替代）；`#msgNav` 点条滚动条维持隐藏。
- 真窗验证：侧栏内容溢出（540>239）时默认无滚动条 → 滚轮进入侧栏（指针随之进入）后右缘出现 6px 细条且列表滚动 → 指针移出后细条消失。
