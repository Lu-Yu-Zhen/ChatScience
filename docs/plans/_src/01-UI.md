# 墨台 · UI 板块实现策划案

## 一、板块定位与文档说明

### 1.1 板块范围

本板块覆盖墨台（ChatScience）桌面客户端的**全部视觉与交互设计层**：设计语言、配色体系、主题系统、字体与排版、栅格与间距、组件规范、图标体系、动效规范、可访问性。

### 1.2 编制基准与冲突处理原则

本策划案以**当前项目已完成内容为唯一事实基准**。凡策划案（《墨台产品整体策划案（完整版）》第 3 章）与实际已实现 UI 冲突之处，**一律以已实现内容为准**。据此，下述三项冲突已按"项目为准"裁定：

| 冲突项 | 策划案原始表述 | 已实现实际（以此为基准） | 裁定 |
|---|---|---|---|
| 左侧边栏宽度 | 固定约 240 像素 | `#leftPanel` 宽 **280px**，收起竖条态 **52px** | 以 280px / 52px 为准 |
| 主题数量 | 内置六套主题（黑白简约、只此青绿、天空与海、朱砂国风、城南旧事、磨砂玻璃） | 仅实现 **light / dark 双主题 + 跟随系统** | 双主题为已实现基座，六套主题列为待实现扩展 |
| 栅格基准 | 全局 8 像素基准栅格 | 实测为 4px 半栅格混排（间距 4/6/8/12/16/20/28px，字号 10/10.5/11/11.5/12/12.5/13/14/15/16/18px） | 以实际 4px 半栅格为准，8px 为主节奏 |
| 图标风格 | 统一线性风格，尺寸固定 16 与 20 像素两档 | 内联 SVG 线性图标，`viewBox 0 0 24 24`、`stroke-width:2`，实际渲染尺寸 11/13/16/20/26px 多档 | 以 24 网格 + 多档渲染尺寸为准 |
| 界面字体 | 未指定具体字体族 | **Instrument Sans**（Google Fonts，400/500/600/700） | 以 Instrument Sans 为准 |
| 字号层级 | 三级（标题/正文/辅助文字） | 实测 10 级字号梯度（10px—18px） | 以实际梯度为准，归纳为 4 个语义层级 |

### 1.3 状态标记约定

全文以三种标记严格区分实现状态：

- **【已实现】** — 已在代码中落地并有验证记录，本期仅需保持与回归。
- **【部分实现】** — 骨架已有，存在缺口或已知缺陷，需补齐。
- **【待实现】** — 尚无任何代码痕迹，需按本策划案从零实现。

## 二、设计语言总纲

### 2.1 定位

**【已实现】** 代码注释明确记载了本产品的视觉定位：**"去 AI 味：中性色 + 墨色主按钮 + 克制蓝链接"**（`01/主页面.html:19`）。

这一定位与品牌名的"墨"字高度自洽，且已在全套令牌中系统落实，应作为长期设计纲领保留：

1. **中性色打底** — 界面大面积使用不带色相倾向的中性灰白（`--bg: #F6F7F9`），不使用任何彩色背景铺底，避免长时间科研工作下的视觉疲劳与"AI 产品感"。
2. **墨色主按钮** — 主按钮不用品牌色，而用近黑的墨色（`--primary-bg: #0F172A`），形成"墨"的视觉锚点与高级克制的质感。
3. **克制蓝链接** — 链接是界面上唯一的常规彩色元素，使用克制的蓝（`--link: #2563EB`），仅用于可点击文本，不做装饰。
4. **零 emoji** — 主页面文件内 emoji 数量为 **0**，状态与操作全部由内联 SVG 表达。

### 2.2 设计原则（供后续扩展遵循）

| 原则 | 含义 | 落地约束 |
|---|---|---|
| 内容优先 | 界面不抢内容 | 无彩色背景铺底；装饰仅限细线与留白 |
| 克制的色彩 | 彩色是稀缺资源 | 全局彩色仅用于：链接、状态（成功/警告/危险）、图表。其余一律中性色 |
| 一致性优先于表现力 | 专业用户依赖肌肉记忆 | 主题切换为"换肤"不改版：布局、间距、组件位置、图标形态零变化 |
| 静默的动效 | 动效服务于状态理解 | 150—300ms；绝不因内容更新触发容器动画 |
| 可访问性为硬约束 | 不是可选项 | 正文对比度 ≥ 4.5:1；状态不得仅靠颜色区分；键盘可达 |

### 3.2 令牌的语义分组（用于主题扩展）

**【已实现】** 现令牌天然分为五组，这是六套主题扩展的映射骨架：

1. **基础层**（`--bg` / `--panel-bg` / `--surface` / `--surface-2` / `--content-bg` / `--main-bg`）——背景与面板
2. **边界层**（`--border` / `--border-soft` / `--panel-border` / `--menu-border`）——分割与描边
3. **文字层**（`--text-1` / `--text-2` / `--text-3`）——三级文字
4. **品牌与交互层**（`--primary-*` / `--link*` / `--accent-*` / `--hover-overlay` / `--conv-active-bg` / `--chip-bg`）——主色、链接、强调、交互反馈
5. **语义状态层**（`--ok*` / `--warn*` / `--danger*`）——成功/警告/危险

**扩展规则**：新增主题只需为这五组各提供一套值，任何主题不得改变组内的**语义关系**（如 `--text-1` 必须比 `--text-2` 对比度更高）。

### 4.2 六套扩展主题策划【待实现】

策划案规划的六套主题为零实现状态。基于已实现的双主题令牌体系，扩展方案如下。

#### 4.2.1 扩展架构

**方案：令牌层扩展（Token-Level Theming），不引入主题引擎依赖。**

```
:root                        → 默认主题（当前 light）
html[data-theme="dark"]      → 暗色主题（已实现）
html[data-theme="ink-green"] → 只此青绿（新增）
html[data-theme="sky-sea"]   → 天空与海（新增）
html[data-theme="cinnabar"]  → 朱砂国风（新增）
html[data-theme="nostalgia"] → 城南旧事（新增）
html[data-theme="glass"]     → 磨砂玻璃（新增）
html[data-theme="mono"]      → 黑白简约（新增）
```

每套主题 = 一份完整的五组令牌赋值 + 可选的材质层（`data-material="glass"` 控制半透明与背景模糊、`data-texture="paper"` 控制底纹）。

**新增令牌（主题扩展必需）**：

| 新增令牌 | 用途 | 缺失后果 |
|---|---|---|
| `--font-ui` | 界面字体族（各主题可微调） | 无法实现"中文衬线可选用于长文献阅读" |
| `--font-serif` | 衬线字体（阅读模式文档正文） | 阅读模式无衬线选项 |
| `--radius-card` / `--radius-btn` / `--radius-tag` | 三级圆角令牌化 | 当前圆角为硬编码数值，主题无法调整圆角气质 |
| `--density` | 密度系数（舒适 1.0 / 紧凑 0.85） | 无法实现"信息密度两档" |
| `--texture-opacity` | 底纹不透明度 | 朱砂国风/城南旧事无法叠加极淡底纹 |
| `--panel-alpha` / `--panel-blur` | 面板透明度与模糊半径 | 磨砂玻璃主题无法实现 |
| `--chart-1..6` | 图表配色序列 | 图表无法随主题变色 |

### 8.3 下拉菜单【已实现 — 含重要架构决策】

**核心问题与解法**：`.dropdown-menu` 类默认 `opacity: 0; pointer-events: none`（配合父级 `.open` 解除）。这导致两类故障：

1. 智能体/权限/模型菜单由 JS 直接切 `display`、父级不挂 `.open` → 菜单"打开"后**透明且不可点**（表现为"点击无响应"）。**修复**：按 ID 特异性覆盖 `opacity: 1; transform: none; pointer-events: auto`。
2. `.input-box` 的 `overflow-y: auto` **裁剪**向上弹出的绝对定位菜单（实测 `elementFromPoint` 命中 textarea）。**修复**：实现 **`openDropdownMenu` / `closeDropdownMenu` 门户（Portal）**——打开时把菜单挂到 `body` 下用 `position: fixed` 动态定位（`left`/`width`/`bottom` 由 `getBoundingClientRect` 计算），关闭时归位。

**规范（后续所有下拉必须遵守）**：
- 一律使用门户方案，不在有 `overflow` 的容器内做绝对定位弹层
- 默认隐藏态用 `opacity + pointer-events`，不用 `display: none`（保证过渡动画）

### 10.3 动效红线【已实现，必须遵守】

1. **内容更新绝不触发容器动画** — 侧栏 `transition` 仅在 `.anim` 类下启用；会话列表/项目列表用**签名守卫**跳过重建（内容未变零重建），激活变化仅**原位切换类**，不触发动画，也不触碰 `updatedAt`。
2. **hover 不引起布局位移** — 统一用 `background` / `color` / `box-shadow` / `transform`；唯二例外：`.btn:hover translateY(-1px)`（按压抬升）与 `.menu-item:hover padding-left: 14px`（刻意缩进）。
3. **`prefers-reduced-motion` 全量降级【已实现】** — `:468-471` 对该媒体查询做了全量动画降级处理。

### 10.4 性能约束【已实现 — 血泪教训】

| 问题 | 根因 | 修复 |
|---|---|---|
| 消息渲染 540ms | 每条用户消息行都给 `img.src` 赋 base64 头像 → 每次 **80ms** 同步解码 | 改 **Blob URL 共享** → 渲染降至 **50ms** |
| 右栏重建 280ms | `renderRightPanel` 无守卫反复重建 | **签名守卫**（作用域+文件+选中态+搜索+折叠+扫描时间戳）→ 常驻 **0ms** |

**规范**：严禁对图片元素重复赋 base64 数据源；任何列表渲染必须带签名守卫。

## 十二、主题无关性原则（硬约束）

**【已实现为设计意图，待实现为跨主题验证】**

策划案第 3.6.6 条的核心原则——"主题切换是换肤而非改版"——与已实现的令牌架构完全兼容，应作为**硬约束**执行：

**主题切换只允许改变**：
- 背景色、面板色、文字色、主色、强调色
- 材质质感（磨砂玻璃的半透明与背景模糊、朱砂国风与城南旧事的极淡底纹）

**任何主题下必须保持恒定**：
- 三栏骨架、左栏 280px / 竖条 52px / 右栏 320px
- 左栏结构、主区五段式结构、组件位置与顺序
- 栅格与间距、圆角层级、字号层级、图标形态与尺寸、输入区布局

**验收方式**：以同一份页面截图在六套主题下逐项比对几何量（元素位置、尺寸），**必须像素级一致**，仅颜色与材质不同。

### 15.3 B 组：已识别缺陷修复（P0）

这些是调研中实测发现的真实缺陷，优先级高于任何新增能力。

| # | 缺陷 | 现象 | 修改方向 |
|---|---|---|---|
| B1 | **无活动会话点发送无反馈** | `sendMessage` 直接 `return`，用户点击后界面无任何响应，易被判定为"卡死" | 在 `return` 前补 `toast('请先选择或创建一个会话')`；若当前在欢迎态，则改为新建会话后直接发送 |
| B2 | **智能体/权限/模型菜单透明不可点** | 菜单由 JS 直接切 `display`、父级未挂 `.open`，导致 `opacity:0; pointer-events:none` 仍然生效 | 统一改为门户方案 `openDropdownMenu` / `closeDropdownMenu`；按 ID 特异性覆盖 `opacity:1; pointer-events:auto` 作为兜底 |
| B3 | **下拉菜单被输入框裁剪** | `.input-box` 的 `overflow-y:auto` 裁剪向上弹出的绝对定位菜单（`elementFromPoint` 命中 textarea） | 一律走门户：打开时挂到 `body` + `position:fixed`，`left`/`width`/`bottom` 由 `getBoundingClientRect` 计算，关闭时归位 |
| B4 | **PDF 重渲染重影** | 未清空旧 canvas/textLayer/标注层 | 重渲染前显式清空三层 DOM，再重建 |
| B5 | **侧栏动画误触发** | 切会话时侧栏出现无意义动画 | 确认 `transition` 仅挂在 `.anim` 类下；会话列表用签名守卫跳过重建 |

**验收方法**：B1 手动点击验证有 toast；B2/B3 在深度较深的会话中向上弹菜单，确认可见且可点；B4 连续翻页 10 次确认无重影；B5 快速切换 20 个会话观察侧栏静止。

### 15.4 C 组：主题系统扩展（P1）

**前置**：A 组必须完成，否则新增主题无法覆盖硬编码颜色，会出现"换主题后局部颜色不变"。

**修改方向**：

1. **新增扩展令牌**（4.2.1 节清单）——`--font-ui` / `--font-serif` / `--radius-card` / `--radius-btn` / `--radius-tag` / `--density` / `--texture-opacity` / `--panel-alpha` / `--panel-blur` / `--chart-1..6`。这些是六套主题的**必要条件**，缺一不可。
2. **落地 12 份令牌赋值**——六套主题（mono / ink-green / sky-sea / cinnabar / nostalgia / glass）各配明暗两版，按 4.2.2 节给出的完整映射表逐条写入。
3. **材质层**——`data-material="glass"` 控制半透明与背景模糊、`data-texture="paper"` 控制底纹；磨砂玻璃主题的**可读性红线**必须遵守：正文与节点文字用实色，代码区与图表区背景不半透明。
4. **对比度自动校验**——保存自定义主题前，自动计算 `--text-1` 对 `--bg`、`--text-2` 对 `--surface` 的对比度，低于 4.5:1 拒绝保存并提示具体令牌。
5. **主题无关性回归**——按第十二章的验收方式，同一页面在六套主题下截图逐项比对几何量，**必须像素级一致**，仅颜色与材质不同。
