# 墨台 · 前端板块实现策划案

## 一、板块定位与冲突处理原则

### 1.1 板块范围

本板块覆盖墨台桌面客户端的**前端工程层**：技术栈与架构、模块划分、构建链路、状态管理、前后端通信、事件驱动、i18n、性能优化、工程化与测试。

与 UI 板块的分界：UI 板块定义"长什么样"，本板块定义"怎么搭、怎么跑、怎么扩"。

### 1.2 冲突处理原则

凡策划案（第 4 章 前端设计规划）与已实现内容冲突，**一律以已实现为准**。据此裁定的主要冲突如下：

| 冲突项 | 策划案原始表述 | 已实现实际（以此为基准） | 裁定 |
|---|---|---|---|
| 前端框架 | React + TypeScript，构建工具 Vite | **原生 JavaScript 单文件前端**，无框架、无构建器（除自研拼接脚本） | 以原生实现为准，React 迁移列为长期演进项 |
| 桌面外壳 | 推荐 Tauri 为长期方向，首期可用 Electron | **Electron 33**（已完整落地，含打包链路） | 以 Electron 为准，Tauri 迁出本期范围 |
| 状态管理 | Zustand 或 Redux Toolkit | **自研状态区 + 快照持久化 + localStorage 回灌** | 以自研方案为准 |
| 前端模块化 | 组件按模式与功能域分模块懒加载 | **13 个模块构建期拼接为单一 IIFE**，共享同一闭包作用域；主脚本 38 万字符内联于 HTML | 以拼接模型为准，ESM 化列为二期 |
| 运行期事件通信 | SSE 或 WebSocket | **SSE**（已实现，未使用 WebSocket） | 以 SSE 为准 |
| 交互确认模式 | "确认模式" | 权限模式下拉（五档，实际名称为"默认确认"等） | 以已实现名称为准 |
| 虚拟滚动 | 长消息与日志用虚拟列表与分页 | **未实现**（消息全量渲染；列表用签名守卫优化而非虚拟化） | 虚拟滚动列为待实现 |

### 1.3 状态标记约定

- **【已实现】** — 已落地并有验证记录
- **【部分实现】** — 骨架已有，存在缺口或已知缺陷
- **【待实现】** — 尚无代码痕迹

## 二、已实现架构总览

### 2.1 架构全景【已实现】

```
┌─────────────────────────────────────────────────────────────┐
│  Electron 主进程（main.ts）                                  │
│  窗口/托盘/全局快捷键/单实例锁/IPC 白名单/180ms 状态落盘      │
├─────────────────────────────────────────────────────────────┤
│  preload.ts — contextBridge 安全桥（CS_BACKEND / IPC 通道）   │
├─────────────────────────────────────────────────────────────┤
│  渲染层 renderer/index.html（构建产物，单文件 536KB）         │
│  ┌───────────────────────────────────────────────────────┐  │
│  │ ① 主脚本（webapp.js ← webapp.ts，30 万字符）           │  │
│  │    Chat 模式 + 通用 UI + 设置/模型配置/知识库          │  │
│  ├───────────────────────────────────────────────────────┤  │
│  │ ② Work bundle（13 模块 → 单一 IIFE，17.7 万字符）      │  │
│  │    00-core 10-api 20-store 30-agents 35-skills        │  │
│  │    40-mcp 45-sandbox 50-notebook 55-run 60-trace      │  │
│  │    70-agent-chat 80-i18n 90-boot                      │  │
│  ├───────────────────────────────────────────────────────┤  │
│  │ ③ 桌面桥接脚本（CS_BACKEND 注入 + 状态回灌 + 差量同步）│  │
│  └───────────────────────────────────────────────────────┘  │
├─────────────────────────────────────────────────────────────┤
│  Node/Express 后端（server/，127.0.0.1 + Bearer token）       │
└─────────────────────────────────────────────────────────────┘
```

### 2.2 关键设计决策（已实现，需在文档中固化）

| 决策 | 理由（源码/报告记载） |
|---|---|
| **不迁移 React/Vue** | 现有单文件前端是"经多轮验收打磨的成熟 UI 资产，重写风险远大于收益"。Electron 直接承载该前端 + Node/Express 后端即满足"独立前端界面与后端服务"的核心目标 |
| **无前端构建器（除自研拼接）** | 作为纯本地桌面应用，前端资源不从网络分发，构建期拼接到单文件反而消除了资源加载与路径解析的复杂度 |
| **测试脚本用 JS 而非 TS** | 验证脚本本身就是行为安全网，同步改写会削弱验证能力 |
| **状态同步 180ms 防抖 + 原子写** | 交互类操作走 IPC 即时（<10ms）；持久化用 180ms 差量检测 + tmp+rename 原子写，兼顾实时性与磁盘写入成本 |

## 四、构建链路

### 4.1 三脚本拼接模型【已实现】

构建脚本 `build.ts` 按**严格顺序**执行三个内联步骤（顺序不可调换）：

| 步 | 脚本 | 作用 |
|---|---|---|
| ① | 主脚本（`webapp.ts` 编译产物 `webapp.js`） | 注入 Chat 模式 + 通用 UI |
| ② | Work bundle（13 个 `work/*.js`） | 拼接为单一 IIFE 注入 |
| ③ | 桌面桥接脚本 | `CS_BACKEND` 注入 + 状态回灌 + 差量同步 |

### 4.2 拼接实现细节【已实现】

| 机制 | 实现 |
|---|---|
| 文件收集 | `listWorkFiles()` 按正则 `/^\d\d-[A-Za-z0-9_-]+\.js$/` 过滤后 **`.sort()` 字典序**（不依赖文件系统返回顺序） |
| 顺序断言 | **断言首个必须 `00-core.js`、末个必须 `90-boot.js`**，违反即抛错 |
| 语法门禁 | 逐文件起 `node --check` 子进程校验语法，任一失败立即中止构建 |
| IIFE 包裹 | 全部模块拼进 `(function(){\n'use strict';\n` + `parts.join` + `\n})();` |
| 注入标记 | `<!--CS_MAIN_SCRIPT-->`、`<!--CS_WORK_MODULES-->`（含其后注释）、`<!--CS_DESKTOP_BRIDGE-->` |
| **函数式替换（关键）** | 注入必须用**函数式 replace**，否则源中 KaTeX 的 `$$` 定界符会被当作特殊替换模式改写（`$&` / `$1` 语义） |

### 4.3 产物断言【已实现】

构建完成后执行 5 项断言，任一失败 `process.exit(1)` 阻止启动：

1. 产物中**无残留** `CS_WORK_MODULES` / `CS_MAIN_SCRIPT` 字面量
2. 恰含 **1 个** `CS_DESKTOP_BRIDGE`
3. 主脚本体量 < 桥接
4. work bundle 体量 < 桥接，且 > 主脚本（以 `id="modeSwitcher"` 定位）
5. `<title>ChatScience</title>` 未被改动

**实测产物一致性**：新旧 build.js 产物 SHA256 完全一致（510,972 bytes）——迁移未改变任何渲染层行为。

### 4.4 bridge 脚本职责【已实现】

| 职责 | 实现 |
|---|---|
| 后端桥接注入 | 暴露 `CS_BACKEND`（IPC 模式 / HTTP 模式双通道） |
| 状态恢复 | 启动时回灌 localStorage（双实例共享持久化状态） |
| 默认模型 | bailian / qwen3.8-flash |
| 差量快照同步 | **180ms** 防抖；`SNAP_TRIM_BYTES = 6MB`；剥离 `data` / `argsRaw` 大字段；`result` / `reasoning` 截断 2048 字符 |
| 桌面模式降级 | 纯浏览器模式自动隐藏标题栏与占位、回退本地演示模式 |

## 五、状态管理与前后端通信

### 5.1 状态分区【部分实现】

策划案要求前端全局状态分为**UI 状态区、会话状态区、运行态状态区**，以避免运行态事件高频更新影响输入与对话流畅度。

| 分区 | 现状 |
|---|---|
| UI 状态区 | **部分实现**（分散于主脚本与 Work 模块的局部状态，未显式分区） |
| 会话状态区 | **已实现**（`conversations` / `projects` / `models`，随快照落盘） |
| 运行态状态区 | **部分实现**（`_calls` 轨迹数组、`WorkState` 管理页状态；未与 UI 状态隔离为独立区） |

**待实现方案**：显式三区划分，运行态事件只写入运行态区并仅重绘受影响的消息卡片（已有 traceRefresh 的 rAF 节流实践为基础）。

### 5.2 通信双通道【已实现】

| 通道 | 用途 | 实现 |
|---|---|---|
| **IPC** | 桌面交互类操作（通知、置顶、窗口控制、选工作区对话框） | 即时响应（<10ms），preload 暴露白名单方法：`winMinimize` / `winMaximizeToggle` / `winClose` / `onMaxChanged` 等 |
| **本地 HTTP** | 数据类操（状态快照、聊天、全部 `/api/work/*`） | `127.0.0.1` + 随机 **24 字节 token** Bearer 鉴权；端口候选回退 |

**鉴权与安全【已实现】**：
- 仅绑定回环地址（`127.0.0.1`）
- 无 token 请求返回 **401**
- `contextIsolation` 开启 + `sandbox` + IPC 白名单
- 环回**不启用 TLS**（决策理由：环回 TLS 无实际威胁模型支撑，属过度设计；以纵深防御替代）

### 5.3 持久化机制【已实现】

| 机制 | 实现 |
|---|---|
| 状态快照 | `data/state.json`（前端快照，含剥离规则） |
| 工作数据 | `data/work.json`（智能体/技能开关/MCP/沙箱策略/运行历史）——**分区存储**，与 state.json 物理分离 |
| 防抖落盘 | **180ms 差量检测**（`main.ts`），交互操作立即触发保存 |
| 原子写 | tmp + rename（杜绝半写状态） |
| 运行时信息 | `runtime.json`（实际端口、token） |
| 会话存储 | Chat 与 Work 会话数据相互独立（双模式分离的落地保障） |

### 5.4 SSE 事件协议【已实现】

聊天与 Agent 运行均走 SSE。`/api/chat` 的完成帧：

```
data: {"done": true, "ttftMs": ..., "totalMs": ..., "chars": ...}
```

Work Agent 运行（`runWorkTurn`）事件序列：

| 事件 | 负载 | 前端处理 |
|---|---|---|
| `run_start` | 运行元信息 | 初始化轨迹容器与状态行 |
| `notice` | 提示信息 | 状态行提示 |
| `delta` | 文本增量 | 逐 delta 渲染正文（**33ms 节流**） |
| `reasoning` | 思考增量 | 思考折叠块（12px 小字，`max-height: 240px`） |
| `tool_start` | 工具名 + 参数 | 追加时间线条目（running 呼吸态） |
| `tool_end` | 结果 + 耗时 | 条目转 ok / error，右对齐耗时 |
| `run_end` | 汇总（步骤数/工具次数/总耗时） | 汇总条「步骤 N · M 次工具调用 · T」 |
| `aborted` | 中断原因 | 渲染为「已中断」（`_pausedByUser` 标记） |

**客户端断开即触发中断【已实现】**：SSE 连接关闭会中止后端运行。

### 5.5 事件幂等与阻塞等待【部分实现】

| 策划案要求 | 现状 |
|---|---|
| 每事件幂等处理（避免重复渲染） | **已实现**（traceRefresh 带重入保护、签名守卫） |
| 工具授权请求**阻塞等待**用户允许/拒绝/本次始终允许 | **待实现**（当前高危拦截由后端 `canUseTool` 直接拒绝并把原因回给模型，前端无授权弹窗交互） |

**【待实现】授权弹窗方案**：

```
触发：后端 canUseTool 遇需人工决策的操作（非硬拦截项）
前端：阻塞式弹窗，展示
  · 来源（哪个智能体 / 哪个步骤）
  · 对象（命令全文 / 文件绝对路径）
  · 风险（命中的危险模式说明）
选项：允许一次 / 本次始终允许 / 拒绝
超时：无操作则按「拒绝」处理（安全默认）
记录：并入运行轨迹（可追溯）
```

## 六、模块化与 TypeScript 化（二期）【待实现】

### 6.1 现状问题

| 问题 | 证据 |
|---|---|
| 前端未模块化 | 13 个 work 模块共享同一闭包作用域，主脚本 38 万字符内联于 HTML |
| 逐行类型检查关闭 | 13 个 `.js` 模块首行均为 `// @ts-nocheck` |
| 单文件规模失控 | 主脚本（webapp）30 万字符 / 5,717 行 |
| 无编译期 i18n 校验 | 现由 build.js 运行时做键集合 diff，非编译期 |

**官方记载的结论**：转 TS 需要先把前端模块化（ESM + 打包器），"硬转只会引入行为风险"，已明确列为后续迭代。

### 6.2 模块化改造方案

**目标**：把 `01/work/*.js` 拆为真正的 **ESM 模块**，主脚本抽取为 TS 源，经打包器产出 bundle，替换现有"字符串内联"模型。

**改造步骤**：

| 步 | 动作 | 风险控制 |
|---|---|---|
| 1 | 建立打包器（**esbuild**，零配置、极快、无运行时依赖） | 与原 build.js 产物做 SHA256 对比，确保逐字节一致后再切换 |
| 2 | 把 13 个模块改为显式 `import` / `export`，消除跨模块的隐式闭包依赖 | 逐个模块改造，每改一个跑一次回归 |
| 3 | 主脚本切分为多文件（按域：chat / layout / settings / kb / reader / msgNav / state / i18n） | 以现有函数边界为切分线，不改逻辑 |
| 4 | 移除全部 `// @ts-nocheck`，改为真类型（复用 `shared/domain.ts` 类型面） | 按域渐进，允许局部 `any` 收口 |
| 5 | i18n 词条改 TS 常量，获得**编译期键校验**（替代运行时 diff） | 中英键一一对应约束由类型强制 |
| 6 | 保留双通道构建：ESM 开发模式（便于调试） + bundle 生产模式（保持单文件分发） | — |

**收益**：编译期类型与 i18n 校验、可控的文件规模、可测试性、可 tree-shaking、支持懒加载。

### 6.3 组件懒加载【待实现】

策划案要求"组件按模式与功能域分模块懒加载，首屏只加载当前模式所需代码"。

**方案**：以域为切分单元（Chat 域 / Work 管理域 / 阅读器域 / 笔记本域 / 沙箱域），非当前模式与非常用页面用动态 `import()` 按需加载。

**注意**：桌面应用资源本地读取，懒加载的收益主要在**启动解析时间**与**内存占用**，需实测确认（当前 bundle 536KB，解析成本可控）。建议**优先级低于模块化本身**。

## 七、国际化【已实现】

### 7.1 规模与机制

## 八、性能优化

### 8.1 已实现优化【已实现】

| 问题 | 根因 | 修复 | 效果 |
|---|---|---|---|
| 消息渲染慢 | 每条用户消息行都给 `img.src` 赋 base64 头像 → 每次 **80ms 同步解码** | 改 **Blob URL 共享** | 540ms → **50ms** |
| 右栏切换闪动/慢 | `renderRightPanel` 无守卫反复重建 | **签名守卫**（作用域 + 文件 + 选中态 + 搜索 + 折叠 + 扫描时间戳） | 280ms → **0ms**（常驻） |

| 切会话动画干扰 | 切会话播放脉冲动画 | **移除**切会话脉冲与强制展开项目；记录点击零动画；动画仅在"左栏收起按钮 / Ctrl+Alt+L / 阅读模式进出"时启用 | 页面稳定 |

### 8.2 性能红线【已实现，必须遵守】

1. **严禁对图片元素重复赋 base64 数据源**（必须用 Blob URL 共享）
2. **任何列表渲染必须带签名守卫**（内容未变零重建）
3. **内容更新绝不触发容器动画**（`.anim` 类门控）
4. **流式输出必须节流**（33ms 档）
5. **退出阅读模式先恢复左栏再重渲染**（避免闪烁）

### 13.2 A 组：主线脚本切分（P0 — 最大技术债）

| # | 动作 | 说明 |
|---|---|---|
| A1 | 定义主脚本的域边界 | 建议：核心工具 / 会话存储 / 消息渲染 / 输入区 / 左栏 / 右栏 / 阅读器 / 文件选择 / 弹窗 / 模型配置 / 公告与设置 |

### 13.3 B 组：状态三区显式划分（P0）

**问题定位**：现状为「快照 + localStorage 回灌 + 分区存储 + 180ms 防抖 + 原子写」，机制完整但**UI 态 / 会话态 / 运行态三者未在数据模型中显式区分**，导致偶发的"重渲染覆盖运行中状态"类问题难以定位。

| # | 动作 | 说明 |
|---|---|---|
| B1 | 定义三区边界 | **UI 态**（面板开合、选中项、滚动位置，纯前端、可丢弃）／**会话态**（消息、配置、笔记，需持久化）／**运行态**（流式输出、工具执行、进度，生命周期短、不持久化） |
| B2 | 分区命名空间化 | 三区分别独立命名空间，禁止跨区写入；运行态不得进入 localStorage |
| B3 | 防抖策略分级 | 会话态沿用 180ms 防抖 + 原子写；UI 态同步写；运行态仅内存 |
| B4 | 回灌时区隔离 | 启动回灌只恢复会话态与部分 UI 态，运行态一律重置为初始值 |

**验收方法**：运行中刷新页面，确认流式输出被安全丢弃、会话内容完整保留、无脏状态残留。

### 13.4 C 组：构建体系升级（P1）

| # | 动作 | 说明 |
|---|---|---|
| C1 | 引入 esbuild | 替换手写拼接，获得真正的模块解析与 tree-shaking；保留现有拼接脚本作为**回退路径**，双轨跑通后再切换 |
| C2 | 建立源码映射 | 开启 sourcemap，使浏览器调试可直接定位到源文件（当前受拼接影响定位困难） |
| C3 | 构建产物断言迁移 | 把 5 项产物断言改写为 esbuild 插件形式，构建失败即中断 |
| C4 | 保持前端 JS 不变 | 注意：**前端因字符串内联模型而保持 JS**，tsc 仅覆盖服务端与共享层；不要顺手把前端迁 TS |

**验收方法**：新旧构建产物做行为等价比对（DOM 快照 + 请求序列），并核对产物体积无异常增长。

### 13.5 D 组：双模式动态能力清单（P1）

**问题定位**：Chat/Work 双模式的**骨架共享、菜单 3/9 项、输入区差异、模式跟随记录**均已实现且验证通过；但功能菜单为**静态渲染**，新增能力需改代码。

| # | 动作 | 说明 |
|---|---|---|
| D1 | 能力清单数据化 | 把各模式的功能项抽为 JSON 清单（名称、图标、通道、可用性条件），渲染层读清单 |
| D2 | 可用性条件声明式 | 每项声明其依赖（如需 Work 模式、需已选工作区、需已配置模型），渲染层按条件自动禁用并给出原因提示 |
| D3 | 欢迎区与快捷按钮组接入 | 见 UI 板块 7.4：中央欢迎区按模式动态加载文案与图标；快捷按钮组由清单驱动生成 |
| D4 | 静默回落补提示 | 现状「模式严格跟随记录 + 静默回落」——回落到默认模式时应给一次性提示，避免用户困惑 |

**验收方法**：新增一个功能项，仅改 JSON 不改代码即可在界面出现；切换模式后菜单项、欢迎文案、快捷按钮组同步正确。

### 13.8 施工顺序建议

```
A 组（脚本切分）→ B 组（状态三区）→ C 组（构建升级）→ D 组（动态清单）→ E 组（工程化）
      ↓                                                                         ↓
  每抽一域即跑全量验证脚本                                            纳入 CI 后转为自动门禁
```

**关键纪律**：A、C 两组属**纯重构**，验收标准是「行为完全不变」——不得借重构之机顺手改功能，否则问题无法归因。
