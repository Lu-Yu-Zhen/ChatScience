壹 · 产品介绍

一个工作台，两条互不干扰的引擎

通用对话工具把一切塞进同一个对话框，科研流程却是有阶段的：先要快速问清楚，再要一步步把实验跑通。墨台把这两件事拆成两套引擎，各自的界面、上下文与运行方式都是为它自己设计的。

Chat

轻量对话

为「马上想知道答案」而设计

  • 即时问答与长文献速读，支持整篇论文注入上下文
  • 报告、文案与通用编程任务
  • 对话仅存本地，不上传
  • 会员档位下基础模型无限畅用

墨道

Work · 多智能体

为「把一件事做完」而设计

  • 可视化智能体工作台，逐步串联科研流程
  • 沙箱内真实执行代码：Python、NumPy、Matplotlib
  • Jupyter 式研究笔记，智能体写入的笔记立即可编辑
  • 全流程轨迹可追溯：工具名、参数、耗时、输入响应
一 双引擎分离 Chat 与墨道在界面、上下文与计量上完全独立。轻对话不占用科研任务的资源，科研任务也不被对话历史拖累。
二 科研全流程技能覆盖 内置文献精读、消融实验设计、数据分析、学术绘图、论文审校、框架复现等科研技能，覆盖从读文献到成稿的关键环节。
三 沙箱内真实执行 代码在独立进程里真跑，产物回传。超时强杀无残留、路径守卫、危险操作静态拦截，可声明断网运行。
四 可插拔的科研 MCP 生态 内置科研工具集，同时支持接入外部 MCP 服务。工具可见范围随档位开放，避免无效工具干扰。
五 本地优先 数据默认留在本机，模型 Key 仅存于本机后端，不随界面状态落盘。
六 克制的界面 中性色打底、墨色主按钮、克制的蓝链接，界面内零 emoji。为长时间科研工作设计，不喧宾夺主。

为什么敢把过程摊开

  • 工具名与参数以等宽字体原样呈现，不做美化包装
  • 每步耗时独立标注，便于定位真正的瓶颈
  • 节点状态区分运行中、完成与失败，失败不隐藏
  • 用户中断的任务标记为「已中断」，不伪装成错误

能力边界，如实说明

  • 沙箱定位是「防误操作」，静态拦截可被绕过，我们不宣称绝对隔离
  • 断网为声明式控制，不宣称绝对安全
  • 知识库检索为词法检索，不是全语义向量检索
  • 不承诺自动产出论文或保证实验结论，研究结论仍需研究者把关

主动说明边界，是专业工具应有的诚实。

    贰 · 常见问题

    先把该说清楚的说完

    01Chat 和墨道有什么区别？

    它们是两套独立引擎。Chat 面向「马上想知道答案」——即时间答、文献速读、报告与通用编程，零配置，打开就能用。墨道面向「把一件事做完」——可视化工作台里搭建智能体、连接科研工具、在沙箱里真跑代码，一路跑到结论与记录落盘。

    两者在界面、上下文与计量上互不干扰：轻对话不会占用科研任务的算力，科研任务也不会被冗长的对话历史拖慢。

    02不付费能用吗？

    能，而且不是「只能看一眼」。注册即赠 200 初始积分，按基础工作流约 1 积分一次计算，足以跑通相当数量的完整流程；每日签到再领 100 积分，签到积分与套餐积分合并使用、遵循相同有效期。

    免费档的能力边界也如实列出：Chat 基础模型按每日限额使用（不享无限、不赠送高阶 Token），不能单独设置子智能体模型（强制跟随主模型），仅开放少量基础技能，不支持手动编排、快照与 fork，高级 MCP 全部关闭，模板最多保存 2 套，知识库仅支持本地极简文档上传（不提供向量库与数据库）。

    03为什么积分和 Token 是两套额度？

    因为它们回答的是两个不同的问题。余额决定「这一次能不能跑起来」——Chat 的高阶模型按 Token 计量，墨道的任务按积分计量，只要余额大于 0 就能运行。档位决定「能用哪些高级功能」——技能范围、MCP 等级、迭代次数、存储容量。

    两者彻底解耦、互不占用。所以买积分不会解锁功能，买会员也不会额外送算力。这不是为了复杂，而是为了让「我这次为什么不能跑」和「我为什么点不了这个按钮」两个问题的答案各自清晰。

    04任务按次收费吗？积分怎么算出来的？

    基础工作流约 1 积分一次，之后按任务复杂度上浮：每增加一个智能体 +0.5，每 10 次工具调用 +0.3，每一轮审辨迭代 +1.0，沙箱执行按 30 秒内 +0.2 / 30–120 秒 +0.5 / 超过 120 秒 +1.0 分档，仿真解析 +2.0 起，批量文献每 10 篇 +1.0。

    阶梯计价对用户透明：任务启动前显示预估消耗，任务结束后显示实际消耗与计算依据。中途中断按已完成步骤计量，不会让用户为没跑完的任务全额付费。

    05套餐额度会结转吗？

    按月发放，当月有效、月底清零、不结转。签到获得的积分与套餐积分合并使用，遵循同一套有效期规则——不做两套有效期，避免用户需要同时记两本账。

    06会员到期了，账户里的积分会作废吗？

    不会。到期只收回权益：高级功能权限、知识库超额容量、Chat 基础模型无限畅用。而余额保留：账户内剩余积分与剩余高阶 Token 都可以继续消耗，你以免费用户身份继续运行墨道基础能力。

    换句话说，你已经买的算力不会因为到期而作废。这也是为什么在数据结构上，余额账户与会员订阅是两条独立生命周期。

    07买充值包会解锁高级功能吗？

    不会。充值包只补充算力，不附带任何会员功能权益。积分用完后你可以单独购买积分继续跑墨道基础任务，但高级功能仍然需要对应档位才解锁。这条边界是刻意划死的，不打算为短期转化而模糊它。

    08支持哪些支付方式？

    规划的路径是「兑换码激活（冷启动）→ 在线支付（成长期）」。兑换码方案把订单与支付解耦：你可以在任意渠道购得兑换码后在本机激活，无需支付资质与回调服务，适合内测期先验证真实的付费意愿。在线支付通道集成中，支持微信支付、支付宝、抖音支付与云闪付。

    本页的支付流程为交互演示，未接入真实支付与账本。

    09沙箱是绝对隔离的吗？

    不是，我们也不会这样说。沙箱提供的是真实执行 + 危险操作静态拦截 + 独立进程隔离 + 超时强杀 + 路径守卫，定位是「防误操作」而非「防恶意突破」。静态拦截存在被绕过的可能，声明式断网也无法被强制保证。

    把边界说清楚，比给一个漂亮但守不住的承诺更有用。

    10我的数据和模型 Key 存在哪里？

    本地优先。数据默认留在本机，模型 Key 仅存于本机后端，不随界面状态落盘。免费用户的对话也只保存在本地。
