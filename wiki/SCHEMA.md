# 墨台 Wiki · Schema 约定

> 本文件是 Wiki 系统的"配置契约"。它告诉任何接入本项目的 LLM 智能体：Wiki 如何组织、页面遵循什么格式、执行摄取/查询/维护时走什么流程。**每次操作 Wiki 前先读这里。**
>
> 模式来源：Karpathy《LLM Wiki》(gist 442a6bf)。三层架构 = 原始资料（不可变）→ Wiki（LLM 维护）→ Schema（本文件）。

## 一、三层架构

| 层 | 位置 | 归属 | 可否修改 |
|---|---|---|---|
| **原始资料 Raw** | 仓库既有文档（策划案 `_src/*.md`、`MEMORY*.md`、迁移说明、验证报告、各 `*-report.md`、源码本身） | 用户 / 构建产物 | ❌ 只读，永不改动 |
| **Wiki** | `wiki/` 目录下全部 `.md` | LLM 完全拥有 | ✅ LLM 创建、更新、交叉引用 |
| **Schema** | 本文件 `wiki/SCHEMA.md` | 人与 LLM 共同演化 | ⚠️ 仅在约定需要调整时改，且记入 log |

核心区别：Wiki 不是"查询时重新检索"的 RAG，而是**编译一次、持续维护**的沉淀物。新资料进来时，LLM 读取、提炼、并入既有页面（更新实体页、修订主题综述、标注与旧结论的矛盾），知识随每份资料和每次提问不断增值。

## 二、目录结构

```
wiki/
├── SCHEMA.md          # 本文件：约定与工作流
├── index.md           # 内容目录：所有页面的分类清单（LLM 每次摄取后更新）
├── log.md             # 时间线：append-only 操作记录
├── overview.md        # 顶层综述：整个项目的全景导航（读这里入门）
├── sources/           # 每份原始资料一个摘要页
│   └── <资料名>.md
├── entities/          # 实体页：模块、组件、系统、角色（"是什么"）
│   └── <实体名>.md
└── concepts/          # 概念页：模式、决策、约定、踩坑（"为什么/怎么做"）
    └── <概念名>.md
```

命名：小写短横线 `kebab-case`，中文实体可保留中文名（如 `entities/墨道.md`）。文件名即页面唯一标识，交叉引用用相对链接。

## 三、页面格式

每个 Wiki 页面顶部带 YAML frontmatter，供检索与 Dataview 类工具消费：

```markdown
---
type: source | entity | concept
title: 页面标题
tags: [标签1, 标签2]
sources: [引用的原始资料路径]   # 可溯源
updated: 2026-09-18
---

# 标题

一句话摘要。

## 正文
...用 [[相对链接]] 或 markdown 链接指向其它页面...

## 关联
- 相关实体：[墨道](../entities/墨道.md)
- 相关概念：[BYOK 认证](../concepts/byok-auth.md)
```

约定：
- **链接优先**：交叉引用是本 Wiki 的价值核心。提到已有页面的实体/概念时务必链接，不要重复展开。
- **可溯源**：结论标注来源资料；矛盾处显式写出"⚠️ 与 X 冲突"并链接，不静默覆盖。
- **一页一主题**：实体页聚焦"它是什么、由哪些部分组成、和谁交互"；概念页聚焦"为什么这样设计、约束是什么、踩过什么坑"。
- **克制篇幅**：概览 + 链接优于堆砌。细节留在原始资料里，Wiki 负责索引与综合。

## 四、操作工作流

### Ingest（摄取新资料）
1. 读原始资料，与用户确认要点（可选）。
2. 在 `sources/` 建摘要页。
3. 更新受影响的 `entities/` 与 `concepts/` 页面（一份资料可能触及 10+ 页）。
4. 新实体/概念缺页则建页。
5. 标注与既有内容的矛盾或补充。
6. 更新 `index.md` 目录。
7. 向 `log.md` 追加一条记录。

### Query（查询）
1. 先读 `index.md` 定位相关页面，再钻取。
2. 综合回答并给出引用链接。
3. **有价值的回答回填**：对比表、分析、新发现的关联——写成新的 concept/source 页，让探索也沉淀。

### Lint（健康检查，定期）
检查：页面间矛盾、被新资料推翻的过时结论、无入链的孤儿页、被提及却缺页的重要概念、缺失的交叉引用、可补的数据缺口。发现问题即修复或记入 log 待办。

## 五、index.md 与 log.md 分工

- **index.md** = 内容导向的目录。按类别（实体 / 概念 / 资料）列出每页 + 一行摘要。查询时先读它。
- **log.md** = 时间导向的流水。append-only，每条以统一前缀开头便于 grep：
  `## [2026-09-18] ingest | 资料标题`。取最近 5 条：`grep "^## \[" log.md | tail -5`。

## 六、演化说明

本 Schema 与项目共同演化。当发现某类页面格式、命名或流程更顺手时，更新本文件并在 log 记一笔。工具（如本地 markdown 检索）按需再加，小规模下 index.md 足够。
