# 宣传合规红线

> 一句话摘要：七条红线的可执行版本——只宣传代码里已经存在的能力、额度表述必须分三条线说清、不宣称绝对隔离、物料先清密钥、学术用途要写边界；其中"待实现不宣传"这一条已经和子智能体的实现进度脱节。

## 七条红线与其可核验依据

出处是策划案 §七.1 的表（`墨台实现策划案/_src/05-宣传.md:371-381`），逐条对现状：

1. **科研辅助定位**：不承诺自动产出论文、不保证实验结论。产品侧一致性证据是系统提示词里的"不得编造事实、数据或引用，超出知识范围要说明"（`app/src/webapp/webapp.ts:4640`）。
2. **额度表述精确**：必须区分 Chat 基础模型无限 / Chat 高阶模型耗 Token / Work 运行耗积分（`墨台实现策划案/_src/05-宣传.md:376`）。这三条线目前只有设计模型，代码里 Token 计量为零实现（`墨台实现策划案/_src/06-订阅预付费.md:17`）。
3. **数据安全如实**：可说本地优先、敏感操作需授权，不得宣称"绝对隔离"，因为沙箱拦截可被绕过是已声明边界（`墨台实现策划案/_src/05-宣传.md:377`），机制见[沙箱边界](sandbox-boundaries.md)。
4. **效果标注真实**：展示要标真实任务与耗时，不用无法复现的对比。
5. **待实现能力不宣传**：团队版、审辨迭代循环、七类子智能体、自动生成 PPT、计费体系（`墨台实现策划案/_src/05-宣传.md:379`）。
6. **密钥与隐私**：物料里不得出现 API Key、PAT 与真实用户文献，截图先清理。仓库层面的配套是含凭据的文件被排除在版本库外（`.gitignore:13-15` 明确写着内含 Qoder PAT 与 AI API Key 的 `app/server/qoder.json`、`app/server/config.json` 禁止入库；同文件还排除了本机 Node 发行版软链 `SDK应用/njs/`，见 `.gitignore:6-7`），Wiki 侧另有禁密钥检查，见[Wiki 系统](../entities/wiki-system.md)。
7. **学术诚信**：不得暗示代写论文、规避查重，需明确"辅助"与"研究者把关"。

另有两条口径纪律：宣传口径必须与《Agent 系统设计》板块第九章的能力边界表严格一致（`墨台实现策划案/_src/05-宣传.md:198`）；团队版卖点与 Slogan 在任何投放中不得启用（`墨台实现策划案/_src/05-宣传.md:213`），内容纪律表把"不宣称待实现能力"再次列为硬约束（`墨台实现策划案/_src/05-宣传.md:299-304`）。

## 现在就会踩线的地方

- ⚠️ 冲突：红线第 5 条把"七类子智能体"列为上线前不得宣传的待实现能力（`墨台实现策划案/_src/05-宣传.md:379`），而运行时已注册七类科研子智能体（`app/src/server/qoder.ts:182`），页面见[子智能体体系](../entities/subagent-system.md) —— 这是"红线过时代"而非违规，应更新红线条目。
- ⚠️ 冲突：站点话术已出现「算力归算力，会员归会员」与「选一个档位，解锁需要的高级能力」（`墨台产品页.html:1237`、`:1400`），而计费体系实质零实现（`墨台实现策划案/_src/06-订阅预付费.md:9`），页面见[账本与计费](../entities/ledger-billing.md)。这条属于红线第 5 条的真实适用范围，投放前要么补实现、要么改表述。

## 操作清单

出物料前按顺序自检：① 逐条把要写的功能在 `app/src` 里找到实现证据（找不到就删掉）；② 额度类表述写满三条线，不写"无限"；③ 安全类表述用"本地优先 + 需授权"，不写"绝对隔离/完全离线"；④ 截图与附件清掉 Key、PAT、真实文献；⑤ 团队/计费/审辨迭代/自动生成 PPT 相关句子一律删除，除非实现已合入；⑥ 学术用途写明"辅助，需研究者把关"。
