# 智能体可观测性

为什么要观测 Agent 运行轨迹：Agent 的失败模式不是崩溃而是**静默偏差**——改了代码没验证、token 花在无效探索上、凭据在配置里裸奔。只有把会话轨迹变成可统计、可检索、可评分的对象，这些缺口才会显形。本项目的三份外部调研给出了同一答案的不同侧面。

## 观测的三个层次

| 层次 | 对象 | 本项目落点 |
|---|---|---|
| 运行时实时轨迹 | 单次回合的工具调用、耗时、步骤 | `app/src/webapp/work/60-trace`（Agent 时间线渲染）+ `55-run` 运行菜单，见 [前端架构](../entities/前端架构.md) |
| 历史会话聚合 | 跨会话 token/成本/工具分布/响应速度 | [AgentsView](../entities/agentsview.md)，旁路读 `~/.workbuddy/projects/*.jsonl` |
| 工作流质量审查 | 任务片段是否闭环（改动→验证→交付） | better-harness 五维评分，见 [Better Harness 报告](../sources/better-harness-report.md) |

## 观测暴露出的真实缺口

- **改而不验**：3/3 会话 8 个任务片段中 13 次编辑、0 次验证命令——直接对应 [验证体系](../concepts/验证体系.md) 已有 12+ 脚本却未被 Agent 自动调用。
- **成本不可见**：28 天 26.7M input token，但多数日期计价为 $0.00——Qoder 自定义端点不在标准定价表，只有 token 计数可信。观测工具会给出"看起来对"的零成本假象。
- **配置面风险**：MCP 明文凭据 + 未固定版本 npx，两个宿主（WorkBuddy / Qoder）独立复现同一问题。
- **信号被噪声淹没**：未跟踪截图占 95.4% 变更行，diff 影响统计失真。

## 诚实性原则（值得借鉴的约束）

better-harness 在证据不足时显式标 `not-evaluable`、必需通道缺失时**拒绝出报告**，而非给一个好看的假分数；正式审查亦把"会话通道过薄"留在证据边界内、行为类结论一律 Unobserved。这与本项目方法论第 3、4 条（失败如实呈现、不谎报指标）同源，见 [验证体系](../concepts/验证体系.md)。

## 环境约束（观测工具的前置条件）

- WorkBuddy 无可管理的插件生命周期（`PLUGIN_LIFECYCLE_UNSUPPORTED`），故依赖宿主插件市场分发的工具全部不可用；旁路读盘是唯一可行路径。
- 目标目录须为**有提交的 git 仓库**，否则 projectHarness 通道不可用。
- 本机 Git Bash 残缺，探测与执行须改用 PowerShell，见 [开发环境约束](../concepts/开发环境约束.md)。
