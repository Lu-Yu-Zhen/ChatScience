# 沙箱机制（隔离执行与诚实边界）

墨台 Work 模式的代码执行隔离方案：**多层纵深防御 + 如实声明边界**，而非宣称不可绕过的隔离。设计立场：沙箱不是安全边界（代码以当前用户权限在本机执行，无容器/Job Object），防护目标是"防误操作、可审计"，对外宣传与 UI 文案必须遵守此口径（见 [宣传合规红线](宣传合规红线.md)）。

## 纵深防御九层（强制力分级）

| 层 | 机制 | 强制力 |
|---|---|---|
| 网络层 | 仅绑 `127.0.0.1` | 强 |
| 鉴权层 | 随机 24 字节 Bearer token | 强 |
| 进程隔离 | contextIsolation + sandbox + IPC 白名单 | 强 |
| 执行层 | `shell:false` + argv 数组（`spawnGuarded`） | **强——唯一不可被沙箱内代码绕过的一层**（命令内容不会被当 shell 元字符执行） |
| 路径层 | `assertInside` + `sanitizeRelPath`（防 junction/symlink 逃逸，作用于工具级文件 API，强制有效） | 强 |
| 写入守卫 | `canUseTool` 对 Write/Edit 强制路径白名单 | 较强 |
| 命令拦截 | `DANGER_PATTERNS` 16 类静态扫描（rm -rf /、mkfs、reg delete 等） | 弱（可绕过，防手滑不防有意） |
| 资源限制 | 超时强杀 + 并发信号量 + 输出上限 + 文件大小上限 | 中 |
| 断网 | 声明式四层近似 | 弱（不可强制） |

## 执行引擎要点

- **目录布局**：`data/sandbox/<scope>/{work,out,.hooks,.meta.json}`；scope = `global`（全局共享）或 `conv-<id>`（会话独立）。SDK cwd 与 run_code 进程 cwd 指向 `work/`，产物建议写 `out/`。
- **工作区模式**：会话绑定本地文件夹后，`options.cwd` 与进程 cwd 同步切换、写入守卫根同步切换；但 `_run_*.py` 运行脚本仍写沙箱目录**不污染用户工作区**；产物 diff 限深 2 层（用户目录可能很大）。
- **超时强杀**：Windows 必须 `taskkill /T /F` 杀进程树（`child.kill()` 杀不掉孙子进程），验证无残留。
- **输出采集**：环形 head 60% + tail 40%（解决进度条刷屏导致尾部结果丢失）。
- **中文/绘图**：`PYTHONIOENCODING/PYTHONUTF8` 防乱码；matplotlib 强制 `Agg` 后端 → dataUrl 回传（≤2MB 内联）。
- **runtimes 探测**：python/node/uv/npm，`where.exe` 解析真实路径（npm/uv 是 .cmd 包装，裸名 spawn 会 ENOENT）；结果 TTL 6 小时落盘 `data/runtimes.json`（每次启动跑 10 个子进程探测有可感知延迟）。
- **策略默认值**：120s 超时 / 256KB 输出 / 并发 2 / 单文件 20MB / network:'declared' / autoGcDays:7（GC 启动时自动跑）。
- **拒绝回传模型**：canUseTool 拒绝原因回给模型，模型可如实转述并调整策略（已验证）。

## 声明式断网（四层近似）

① 代理环境变量指向黑洞 `127.0.0.1:9`；② Python `sitecustomize` monkeypatch socket/net；③ Node `--require netblock.js`；④ 可选静态导入拦截（默认关，误伤面大）。**已声明边界：ctypes / 原生扩展 / C 层 DNS 仍可联网，不可强制**。

## 已知问题（两处，均"有意保留"待修复）

1. **`?force=1` 不生效**：`sandbox.ts` 的 `detectRuntimes` 包装函数 `function (_force?) { return proc.detectRuntimes(appRoot); }` 忽略参数直走 TTL 缓存；routes 层 `req.query.force === '1'` 传进来被丢弃。源码注释明确标记为与迁移前 JS 版一致的遗留行为。修复 = 包装透传 force 一行（backend 策划案阶段一 #2）。
2. **"运行时未安装"错误文案缺右括号**：`+ join(...) || '无' + '）'` 因 `+` 优先级高于 `||`，导致 `||` 分支永不生效且闭合括号丢失。提示性文案不影响功能，修复 = 修正优先级（阶段一 #3）。

⚠️ 另注意 `usage.peakRssKb` 恒为 null 是**设计决策不是 bug**（无 Job Object 无法测量，字段留位不谎报）；真正的资源限制待实现（Job Object、强制断网、白名单优先拦截均为 P1/P2 待办）。
