# 踩坑实录（跨会话汇编）

从验证报告与六份日记忆中汇编的高价值踩坑，每条按「现象 → 根因 → 对策」。原则：**只收录有具体错误信息/命令细节可考的条目**，细节留原文，本页做索引。

## 打包与运行时

### rcedit 写图标竞态
- **现象**：pack 流程中 rcedit 重写 exe PE 图标资源时，若 ChatScience.exe 仍在运行（文件被占用），出现**部分写入静默失败**——rcedit 不报错但图标未更新。
- **根因**：Windows 文件锁。exe 运行中其 PE 资源段不可写；rcedit 对锁定文件的失败模式不总是抛异常。
- **对策**（`app/src/pack.ts` 第 2.5 步固化）：先 `taskkill /IM ChatScience.exe /T /F`，再 `spawnSync(process.execPath, ['-e','setTimeout(function(){},1200)'])` 等待**进程树退出与文件锁释放约 1.2 秒**，然后才调 rcedit；失败则 `process.exit(1)` 显式中止。见 [构建打包体系](../entities/构建打包体系.md)。

### ERR_REQUIRE_ESM：打包版 server 从未启动
- **现象**：首次打包后 Work 模式全部请求失败、选工作区无反应；开发环境完全正常。
- **根因**：`server/qoder.js` 顶部 `require('@qodercn-ai/qodercn-agent-sdk')`——SDK 是纯 ESM 包，系统 Node 24 支持 `require(esm)`，但 **Electron 33 内置 Node 20 不支持**，`ERR_REQUIRE_ESM` 使 server 模块加载失败，所有 `/api/*` 无人监听。
- **对策**：改动态 `import()` 惰性加载（`loadSdk()` 进程内缓存）。连锁坑：**tsc 在 CJS 输出中会把一切 `import()`（含变量指示符）改写为 require 包装** → 用 `new Function` 间接层保留真实 import()。见 [ts-migration](../sources/ts-migration.md)。

### ELECTRON_RUN_AS_NODE 宿主泄漏
- **现象**：从 WorkBuddy 等 Electron 宿主的沙箱会话里 spawn 打包版 exe，进程秒退、runtime.json 不写出。
- **根因**：宿主环境泄漏 `ELECTRON_RUN_AS_NODE=1`，electron.exe 退化为纯 Node，应用不启动。
- **对策**：spawn 前 `delete exeEnv.ELECTRON_RUN_AS_NODE`（exe-verify 固化）。CDP 端口同理必须走**真实命令行参数** `--remote-debugging-port`（appendSwitch 对早期开关不生效）。

### 端口 3218 触发 Windows EACCES
- **现象**：后端绑定 3218 端口报 EACCES（Windows 保留端口段）。
- **对策**：候选端口自动回退（8642 等），实际端口写 `runtime.json`。见 [Electron桌面层](../entities/Electron桌面层.md)。

### ready-to-show 竞态致「打开应用没窗口」
- **现象**：进程活着、任务栏无窗口。
- **根因**：`ready-to-show` 在 `loadFile()` **之后**注册，页面命中缓存加载极快时事件先于监听触发，窗口永远 `show:false`；叠加关窗=隐藏托盘且无单实例锁。
- **对策**：3 秒兜底 `win.show()` + `requestSingleInstanceLock` + `second-instance` 唤起。⚠️ 副作用：重打包前必须杀旧实例，否则新实例静默退出、用户看到的仍是旧代码。

## 模型与 SDK

### resolveModel 回调打回平台额度通道
- **现象**：Work 模式配置 BYOK 模型后仍报 `credit usage limit`——平台付费额度被消耗，即使 resolveModel 回调**恒返回 BYOK 模型 id** 也一样。
- **根因**（2026-09-15 二分实验 `verify/byok-bisect.js` 坐实）：Qoder SDK 服务端把「设置了 resolveModel 回调」的会话整体路由回平台额度通道；per-call CustomModel 注入（返回 `{provider, api_key}`）亦被拒（`Failed to generate custom pool` / `access token rejected`）。
- **对策**：BYOK-only 定案——**不设置 resolveModel**，`options.model` 直接填已注册 BYOK 模型 id（如 `qwen3.8-flash-pg`），全 purpose（含子智能体 inherit/压缩/工具调用）跟随直连模型。另实测 1.0.34 的 QoderModelPurpose 实际值为 `main/plan/task/compact/utility`（≠国际版文档 main/subagent/compact）；lite 档 0 Credit，验证遇额度耗尽可统一降 lite 跑通。见 [BYOK 认证](byok-auth.md)、[后端服务](../entities/后端服务.md)。

### SDK 隔离三件套缺一即泄漏
- **现象**：Work 会话工具列表混入本机数百个 MCP 工具/54 项用户级技能。
- **根因**：SDK 默认继承本机 qoderclicn 全部配置。
- **对策**：`settingSources: []` + `strictMcpConfig: true` + `tools` 白名单**缺一不可**；`init.skills` 只是发现报告，上下文与调用由 `skills` 数组白名单限制。见 [沙箱机制](沙箱机制.md)。

## 浏览器自动化与 UI 验证

### CDP 对隐藏/最小化窗口超时
- **现象**：exe-verify 在沙箱会话跑时 `FAIL | CDP UI 验证流程 | cdp timeout: Runtime.enable`、`[shot] error failed: cdp timeout: Page.captureScreenshot`（exev6/exev7 原始输出）。
- **根因**：窗口最小化/被遮挡时 Electron 冻结 rAF 与渲染 IO（页面 `visibility=hidden`），CDP 的 Runtime 求值与截图等待渲染帧而超时；同现象在验证报告 Round 3 亦有记录（"动画/渲染卡住，转前台即恢复"）。
- **对策**：shot() 包 try/catch 降级为日志不中断主流程；UI 断言优先 computed style / DOM 状态（不依赖合成帧）；需要截图时确保窗口前台。⚠️ 与"沙箱终止 exe 子进程派生（fetch failed → D 类检查 SKIP）"是**两个独立的环境限制**，勿混判为产品 bug。见 [验证体系](验证体系.md)。

### 隐形下拉菜单（DOM 断言证明不了视觉可见）
- **现象**：Agent 下拉"点击无响应"，但 DOM 断言 `display:block`、children 数全对。
- **根因**：`class="dropdown-menu"` 的 CSS 是配合父级 `.open` 的显隐方案（`opacity:0; pointer-events:none`），JS 只切 `style.display`、父级从不挂 `.open` → 菜单透明且不可点。
- **对策**：ID 特异性覆盖（`#agentSelectMenu{opacity:1;pointer-events:auto}`）。**教训：视觉可见性必须在真实窗口用 elementFromPoint/计算样式验证**。

### .input-box overflow 裁剪上弹菜单
- **现象**：权限/模型/加号菜单点击后"消失"，elementFromPoint 实测命中 textarea。
- **根因**：`.input-box` 带 `overflow-y:auto`，绝对定位的向上弹出菜单被祖先滚动容器裁剪。
- **对策**：菜单**挂 body + position:fixed** 门户（openDropdownMenu/closeDropdownMenu），关闭归位；prefSelect 重写同因同治。

### zoom 下 fixed 菜单坐标分裂
- **现象**：界面字号滑条（`body.style.zoom` 0.9–1.1）生效后，fixed 定位菜单偏移 zoom 倍。
- **根因**：body 有 zoom 时 `getBoundingClientRect()` 返回**视觉坐标**，而 `style.left/top` 写入的是**本地 CSS 坐标**（渲染 ×zoom）；`innerHeight` 在 zoom 下同样是视觉值。
- **对策**：`csViewportK()` 一次性 fixed 探针实测比值 k（视觉/CSS，按 zoom 缓存），定位统一除以 k；且向上展开时 top 与 maxHeight 必须由**同一份可用空间**推导（否则菜单被压扁悬空 70px——实测 menuTop 552/bottom 684 vs 按钮顶 756）。

### 字体设置"从未生效"的两层根因
- **现象**：设置页换字体，界面纹丝不动；上一轮"修好了"仍复现。
- **根因**：① 声明层——`applyFontStyle` 改 html 内联，但 body 自带 CSS `font-family:'Instrument Sans'` 阻断继承；② 执行层——`prefPatch` 全代码库**只有 5 处调用、零定义**，change 处理器首行抛 `ReferenceError`，同行 `applyFontStyle(v)` 永不执行。
- **对策**：改 `document.body.style.fontFamily` + 补 `prefPatch` 定义。**教训：此前 14/14 验证全绿仍漏——只测了启动链路（localStorage+reload）与函数直调，没走「点开下拉→点条目」真实点击链**。

### 等宽字体栈的 monospace 顺序坑
- **现象**：请求「等宽黑体」，中文渲染成宋体（NSimSun）。
- **根因**：`--mono` 栈中 `monospace` 关键字排在中文字体**之前**，中文被系统等宽字体接走。
- **对策**：专用栈把 `monospace` 压到最后（拉丁走 Cascadia Mono、中文走雅黑族）；本机无中文等宽黑体，需严格对齐要另装 Sarasa Mono SC。

## CSS 与脚本注入

### 逗号选择器退化打穿整页底色
- **现象**：壁纸注入脚本生成的规则让**根元素**被加了 `background: transparent !important`，整页底色消失。
- **根因**：CSS 逗号分隔的是**完整选择器**——`html[data-theme="a"], html[data-theme="b"], ... body.x #el {}` 中前面各条全部退化为裸 `html[data-theme="x"]`。
- **对策**：每组共享选择器列表**每条都自带完整后缀**（如 `html[data-theme="x"] body.is-initial-chat #mainHeader`）；验证加「html 根元素未被误加背景」断言守住。同类：壁纸底色写在 style 内联 `background` 简写上（内联恒胜 + 简写重置 background-image）→ **必须 !important**。见 [主题系统](../entities/主题系统.md)。

### Edit 残留尾巴 + appendChild 移动语义
- **现象**：字号滑条刻度行"结构改了但运行时不在原位"（wrapChildCount=1）。
- **根因**：Edit 的 old_string 未覆盖旧结构后续装配行，残留 `fontSizeWrap.appendChild(scaleRow)` 在 new_string 之后执行——appendChild 的**移动语义**静默把节点从新父级拽走，不报错。
- **对策**：替换 UI 构建代码必查 old_string 覆盖范围外的后续装配行；诊断以运行时取证（childCount）一步定位。

### 脚本锚点凭印象拼必失败
- **现象**：注入脚本报「未找到锚点」，一天内踩两次。
- **根因**：目标注释是多行块注释（行尾无 `*/`）、或生成时缩进与印象不符。
- **对策**：写锚点前先 `JSON.stringify` 打印真实片段；注入脚本做成幂等（START/END 标记可重复执行）。

## PowerShell / Windows 环境（详见 [开发环境约束](开发环境约束.md)）

### PowerShell 输出与 Cmdlet 行为坑
- **现象/根因/对策**（本簇可考三条）：① stdout 不直接回显 → 一律 `Set-Content`/`[System.IO.File]::WriteAllText(...,UTF8)` 落盘后读回（中文防 mojibake）；② `Compress-Archive` 写 zip **条目路径用反斜杠**（违反 ZIP 规范 `/`）→ 墨台浏览器端 zip 解析器加 `rawPath.replace(/\\/g,'/')` 归一化；③ node.exe 往 stderr 输出会被 PowerShell 判为 `NativeCommandError`（exev4 原始输出：`DRIVER ERROR: terminated 所在位置 行:445 字符:615 ... CategoryInfo: NotSpecified`）——脚本被误报失败，需重定向或判 exit code。
- ⚠️ 任务侧提及的「数组解包坑」表述在本簇原始资料中**未找到对应记录**，最接近的是上述 ②（Compress-Archive）与管道对象单值/多值行为；如有出处待补录。

### better-harness 两个上游 Windows bug（会话证据恒 0）
- **现象**：`asset-baseline`/session 分析对本机 WorkBuddy 会话 eligible=0。
- **根因**：① slug 推算：`D:\ChatScience` 生成 `D--ChatScience`，实际目录 `d-ChatScience`（盘符大小写 + `:` `\` 各转一横 vs 合并一横）→ `missing-required-root`；② `isWorkspaceMatch()` 纯字符串比较，会话记录小写盘符 `d:\\ChatScience` 被判 foreignCwd 丢弃。
- **对策**：盘符转小写单横线拼接 + win32 下大小写折叠比较（修复后 eligible=3/5）。另：`--until` 归一化为当日 00:00Z 会截掉当天，须传明天。

## 并发与协作

### 跨会话并发编辑事故
- **现象**：08:50 webapp.ts 被旧缓冲覆盖回原始版（设置页 TS 全丢），09:02 产出「新 HTML + 旧 TS」崩坏组合（引用已删的 modelConfigBtn，启动即白屏）；另有 tsc 双进程写入竞态致"同一文件两次构建词条数不同"的假象。
- **对策**：改动前必重读文件（mtime + 标记 grep）；发现回退先 diff 判断事故/重构，确认无他人新工作才逐块重放；构建前跑 mtime 竞态守护；**绝不回退用户改动**。
