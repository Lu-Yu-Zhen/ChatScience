# 领域插件（server/plugins/<domain>/）

按学科领域打包的科研外挂（2026-09-15 引入），把子智能体、技能、命令、MCP 工具四类能力装进一个目录，经 SDK local plugin 机制注入会话。内置三个领域：**research-ai**（人工智能）、**research-robotics**（机器人）、**research-math**（数学）。

## 目录布局

```
app/server/plugins/<domain>/
  .qoder-plugin/plugin.json    # 声明 name / version / description
  agents/*.md                  # 领域子智能体：frontmatter(name/description/model/tools) + 正文=系统提示词
  skills/<name>/SKILL.md       # 领域技能
  commands/*.md                # 领域命令（CLI 原生发现：/plugin:cmd）
  .mcp.json                    # 领域 MCP（stdio server：tools/mcp-mini.js）
  tools.json                   # MCP 工具清单 {server, tools[]}（宿主白名单用）
  configSchema.json            # 参数声明（默认值+说明，前端展示）
  README.md                    # 能力清单与应用示例
```

## 装配语义（宿主解析，不依赖 CLI 发现行为）

- `agents/*.md` → 宿主 `parseAgentMd` 解析后注册进 `options.agents`，key 为 `plugin:agent`，[墨道](../entities/墨道.md) 经 Agent 工具委派（见 [agent-委派模式](agent-委派模式.md)）；
- `skills/*` → 以 `plugin:skill` 限定名追加进 `options.skills`（开关按插件粒度）；
- `tools.json` → 裸工具名转精确名 `mcp__<server>__<tool>` 进主会话与子智能体工具白名单；无 tools.json 则不带 MCP 工具白名单（`.mcp.json` 仍由 CLI 加载）；
- 配置：`configSchema.json` 默认值 + 插件目录 `config.json` 覆盖合并，供工具运行时读取。

## 启用与分发

- 启用状态存 `work.json` 的 `domainPlugins` 分区：**未记录 = 启用，显式 false = 关闭**。
- 双目录扫描：`app/server/plugins/`（内置）+ `app/data/plugins/`（用户上传，`createPlugin` 逐段过滤 `.`/`..` 防目录穿越）；用户目录与内置同名插件**跳过**（保护内置）。
- 管理页入口：设置页「知识与扩展 → 技能与插件」（见 [设置页](../entities/设置页.md)）。

## 为什么用插件形式（设计理由）

- 领域能力可整包增删、可用户上传扩展，不动核心代码；
- 会话作用域加载：本地插件与已安装插件同名时会话内优先，适合开发调试与灰度，不触碰全局安装状态。

## 踩坑 ⚠️

- **插件加载失败是静默的**：路径不存在、frontmatter/`.mcp.json` 损坏均不阻塞 init，损坏内容只是不出现在能力清单里。官方唯一显式诊断是 `reloadPlugins()` 的 `error_count`。若把七类子智能体做成插件分发，必须自建「加载后校验」（`listPlugins()` 比对期望清单）。
- 宿主展示插件清单用 `listPlugins()`，不要用 init 结果的 `plugins` 字段（无稳定结构）。
- 插件子智能体与 SUBAGENT_SPECS 一样受"不可嵌套"约束（tools 不含 Agent）。
