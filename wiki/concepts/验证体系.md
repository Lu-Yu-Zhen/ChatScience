# 验证体系（app/verify/ 脚本族）

墨台以 12+ 个验证脚本代替 CI 承担质量门禁：每层能力有专属脚本，打包产物有系统性 exe-verify，全部遵循「真实执行、失败如实呈现」五原则。脚本源在 `app/src/verify/*.ts`（tsconfig.verify.json 宽松编译），产物 `app/verify/*.js`。

## 脚本清单与覆盖

| 脚本 | 覆盖 | 结果基线 |
|---|---|---|
| `exe-verify.js` | 打包产物系统性验证 **34 项**：A 启动+runtime.json+HTTP API（health/state/bootstrap/skills/qoder config/notes/kb）；B CDP UI 验证（Chat 真实流式、Work 切换、侧栏九入口、墨道渲染、控制台 0 错误）；C 重启恢复（跨重启持久化）；D 沙箱执行+Agent 回合（run_code/note_write/Skill） | 通过（见下方环境边界） |
| `sandbox-verify.js` | 沙箱引擎：中文输出、numpy、超时强杀无残留、matplotlib 产物回传、路径守卫、环形采集、声明式断网、危险拦截、并发信号量 | 18/18 |

## 方法论五原则（backend 策划案 9.2，值得固化）

1. **行为保持不变**：TS 迁移以 renderer/index.html **SHA256 完全一致**为最强保证；
2. **真实执行**：真实 python、真实外网、真实模型回合，不用 mock；
3. **失败如实呈现**：AI 失败显示【AI 回复失败】，无静默假成功；
4. **不谎报指标**：`peakRssKb` 恒 null 而非填假值；
5. **双通道 UI 验证**：浏览器自动化/CDP + 真实窗口 computer-use。⚠️ 教训（MEMORY）：只测启动链路+函数直调会漏掉真实点击链路 bug（prefPatch 未定义 14/14 全绿仍漏），**UI 交互必须模拟真实点击验证**。

## 关键机制

- **boot-marker.log 回归锚点**：打包版启动确认三条件 = 进程存活 + 端口 8642 监听 + `resources/app/data/boot-marker.log` 出现**新的** `lock=true`（见 [Electron桌面层](../entities/Electron桌面层.md)）。exe-verify 以 `--remote-debugging-port=9223` 命令行参数拉起 exe 获取 CDP 通道（appendSwitch 对早期开关不生效，必须传参）。
- **CDP 观测**：`Page.addScriptToEvaluateOnNewDocument` 注入伪 Electron 桥；`app/_cdp_eval.js "<js>" await` 在主世界求值断言（computed style、DOM 状态）；consoleErrors 全程收集要求 0 错误。
- **环境边界（如实声明）**：exe-verify 在 WorkBuddy 沙箱会话内运行时，安全策略会终止 exe 派生子进程（python/cmd/qodercli）→ D 类检查自动 SKIP，等价验证由 ts-migration-smoke 在 node 侧完成；普通终端运行可全覆盖。
- **未覆盖项**：`/api/chat`（需外网上游）、`/api/work/agent/run`（需 Qoder 云端，用 sdk-smoke 单测）、pack.js 全流程（会拉起 exe，建议桌面会话手动跑）。
- **缺口**：无 CI 门禁（脚本级手动跑，P1 待办）、无契约测试、无性能基准回归。
