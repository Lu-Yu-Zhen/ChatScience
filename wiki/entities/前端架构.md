# 前端架构

墨台桌面客户端的前端工程体系：Electron 33 承载**原生 JS 单文件前端**（无 React/Vue/打包器），由主脚本 webapp + Work bundle 数字前缀模块 + 桌面桥接脚本三段构建期拼接为单一 `renderer/index.html`。

## 是什么

- **分层全景**：Electron 主进程（`main.ts`：窗口/托盘/全局快捷键/单实例锁/IPC 白名单/180ms 状态落盘）→ `preload.ts` contextBridge 安全桥 → 渲染层 `app/renderer/index.html`（构建产物 ≈500KB）→ Node/Express 后端（仅绑 127.0.0.1 + 24 字节随机 token Bearer 鉴权）。
- **主脚本**：`app/src/webapp/webapp.ts`（30 万字符 / 5717 行），承担 Chat 模式、三栏骨架、知识库、阅读模式、右栏、msgNav、状态快照、主 i18n。**规模已到维护临界点，是最大技术债**。
- **Work bundle**：`app/src/webapp/work/` 下数字前缀模块，构建期按字典序拼接进**同一 IIFE、共享同一闭包作用域**（模块间顶层 `const` 互引、不污染全局——这也是 ESM 化的主要障碍）：
  - `00-core`（UI 工厂/ICONS/tt()/Toast）→ `10-api` → `20-store`（WorkState）→ `30-agents` → `35-skills` → `40-mcp` → `45-sandbox` → `50-notebook` → `55-run` → `60-trace` → `70-agent-chat` → `80-i18n`（178×2 词条）→ `90-boot`（i18n 合并+初始化）。
  - ⚠️ 02-前端策划案记载 13 模块；现已新增 `75-plus-menu`（输入框「+」资源挂载菜单，排序落在 70 与 80 之间），实际 14 个。首末仍强制 00-core / 90-boot。
- **桥接脚本**：CS_BACKEND 注入（IPC/HTTP 双通道）、localStorage 回灌、180ms 差量快照同步（SNAP_TRIM_BYTES=6MB、剥离大字段）、纯浏览器降级模式。

## 构建链路（改源码的正确姿势）

1. **只改 `app/src/webapp/` 源码**；`01/` 目录是其同步工作副本、`app/renderer/index.html` 是拼接产物——**两者都是编译产物，勿手改**，详见 [构建产物同步陷阱](../concepts/构建产物同步陷阱.md)。
2. tsc 编译：`tsconfig.webapp.json` 等三配置，`strict:true` + `noEmitOnError:true`（类型不过不出产物）；必须显式 `exclude:["node_modules","dist"]` 否则 TS18003。
3. `node app/build.js` 三段拼接（顺序不可调换）：字典序收集 `/^\d\d-.*\.js$/` → 断言首 00-core 末 90-boot → 逐文件 `node --check` 语法门禁 → IIFE 包裹 → 按 `<!--CS_MAIN_SCRIPT-->`/`<!--CS_WORK_MODULES-->`/`<!--CS_DESKTOP_BRIDGE-->` 标记注入。**注入必须用函数式 replace**，否则 KaTeX `$$` 被当特殊替换模式改写。
4. 构建后 5 项产物断言（无残留标记、恰 1 个桥接、体量关系、title 未动），任一失败 exit(1)。
5. 用户硬约定：每完成一步改动必须重新打包并启动应用验证（`PACK_SKIP_HEAVY=1 node app/pack.js` → explorer 代理启动）。

## 关键决策与踩坑

- **不迁移 React/Vite/Tauri**：单文件前端是多轮验收打磨的成熟资产，重写风险大于收益；本地分发不需要资源路径解析。
- **前端保持 JS**：因字符串内联模型，tsc 仅覆盖服务端与共享层；13/14 个 work 模块首行 `@ts-nocheck`。ESM+esbuild 化是二期方案（先做产物 SHA256 逐字节一致再切换）。
- **通信双通道**：交互走 IPC（<10ms）、数据走本地 HTTP；SSE 流式（8 类事件、33ms 节流、断开即中断）。环回不启用 TLS（威胁模型不支撑）。
- **持久化**：`data/state.json`（快照）与 `data/work.json`（工作数据）分区存储；180ms 防抖 + tmp/rename 原子写。
- **验证方法论**：DOM 断言 ≠ 视觉可见，必须 `elementFromPoint` + 计算样式在真实窗口验证（"下拉点击无响应"根因即此法抓到）。
