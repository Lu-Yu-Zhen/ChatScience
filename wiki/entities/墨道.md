# 墨道（主智能体）

「墨道」有两层含义：广义指 Work 模式整个智能体系统（品牌词，"深科研交给墨道"）；狭义指内置主智能体 `agent-orchestrator`——唯一有权调度子智能体的编排入口。

## 定位

- 复杂科研任务的编排入口：拆解任务并按需委派子智能体，汇总结果后交付；简单问题直接回答，不拉起子智能体。
- 三职责（写进 system prompt）：① 意图识别与动态路由；② 结果汇总与判定；③ 异常处理与重规划。
- 三分支路由策略：简单任务直接回答 / 中度任务调用少数子智能体 / 复杂任务按依赖串联多个；混合任务先科研后自行汇总。
- ⚠️ 04 策划案编制时（2026-09）墨道为"演进目标架构（待实现）"；源码 `app/src/server/qoder.ts` 已落地 `agent-orchestrator` 并注册七类子智能体（见 [子智能体体系](子智能体体系.md)）。对外宣传纪律仍要求：审辨迭代循环、七类子智能体上线前不得宣传（MEMORY.md 红线）。

## 工具集与配置

`BUILTIN_AGENTS` 中的定义（`agent-orchestrator`）：

| 项 | 值 |
|---|---|
| tools.sdk | Read / Edit / Write / Bash / Glob / Grep / WebFetch / WebSearch / **Agent** |
| tools.scienceTools | kb_search, note_write, doi_cite, keyword_expand, figure_caption |
| skills | research-decompose, academic-writing, experiment-log |
| modelKey | `byok`（见 [BYOK 认证](../concepts/byok-auth.md)） |
| permissionMode / maxTurns | acceptEdits / 200 |
| sandbox | scope: global |

**`Agent` 工具是委派开关**：主会话 tools 必须含 `Agent` 才能调起 `options.agents` 注册的子智能体；仅 agent-orchestrator 配置了它，其余智能体经白名单过滤后不可见。机制详见 [agent-委派模式](../concepts/agent-委派模式.md)。

## 委派机制要点

- 每次委派把「当前任务 + 必要材料片段」写进委派提示词——子智能体看不到完整对话。
- 子智能体之间不能互相调度；所有汇总、裁定由墨道完成（SDK 层面子智能体 tools 不含 Agent，不可嵌套，天然支撑"唯一网关"语义）。
- 委派前说明为什么选该子智能体；结果带回后注明出处。
- 领域插件的 `plugin:agent` 子智能体也合并进同一注册表（见 [领域插件](../concepts/领域插件.md)）。

## BYOK 模型通道

墨道（及全部 Work 智能体）的模型调用**只走用户自有 API Key**：`options.model` 直填已注册 BYOK 模型 id，凭据由 Qoder 服务端持有，不消耗平台 credits。无可用 BYOK 模型时明确报错，绝不回落平台档位。详见 [byok-auth](../concepts/byok-auth.md)。

## 内置智能体家族

`BUILTIN_AGENTS` 现状（源码实测）仅 2 个：`agent-orchestrator`（墨道）与 [墨析](墨析.md)（agent-discuss，对话只读）。⚠️ 04 策划案第四章描述为 4 个内置智能体（通用/科研/复现/分析）+ agent-discuss 共 5 id，与当前源码不符——应系后续版本收敛为「编排 + 讨论」双智能体、其余能力改由子智能体承担。以源码为准。
