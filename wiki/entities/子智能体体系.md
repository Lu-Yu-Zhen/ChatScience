# 子智能体体系（七类科研子智能体）

墨道蓝图中的科研分工单元：七类子智能体经 `options.agents` 注册给主智能体 [墨道](墨道.md) 委派，**不进 UI 切换器**。对应策划案 4.4「路径 B：多智能体注册」与 13.6 E 组。

## 七类清单（`SUBAGENT_SPECS`，qoder.ts）

| id | 名称 | 何时用（description 要点） | 权限/轮数 |
|---|---|---|---|
| sub-lit-review | 文献调研 | 检索文献、调研现状、对比方法、找空白；只读 | default / 14 |
| sub-experiment-design | 实验设计 | 实验方案、消融矩阵、因果变量、统计效能；产出设计文档 | default / 10 |
| sub-simulation | 实验仿真 | 沙箱跑代码/训练/复现；小样本先验证再放大 | acceptEdits / 16 |
| sub-data-analysis | 数据分析 | 统计检验、分组对比、出版级图表；结论附数值证据 | acceptEdits / 14 |
| sub-writing | 文稿撰写 | IMRaD 组织、LaTeX 自检、doi_cite 引用、图表注 | acceptEdits / 14 |
| sub-review | 结果评审 | 审辨环节：多维评分 + 缺陷清单 + 论点-证据匹配；只读 | default / 10 |
| sub-archive | 资料归档 | 分类归档、知识片段提取、note_write 分条落盘 | acceptEdits / 10 |

每类 = `whenToUse`（→ SDK `description`，路由依据）+ `prompt`（系统提示）+ `sdkTools` + `scienceTools` + `skills`（预加载专属技能）+ `maxTurns` + `permissionMode`。

## 注册与转换（buildSubagentDefinitions）

`SubagentSpec` → SDK `AgentDefinition`：
- `description = whenToUse`——写成「何时用我」，是路由质量第一等指标；
- `scienceTools` 映射为 `mcp__chatscience__<tool>` 精确名，`mcpServers: ['chatscience']` 字符串引用复用主会话 in-process 科研 server；
- `model: 'inherit'` 继承主会话模型（含 BYOK 直连）；
- **tools 一律不含 `Agent`**（子智能体不可嵌套派生）；
- `maxTurns` 必设（防失控第一道闸）。

## 数据来源与管理页分区

- 定义持久化在 `work.json` 的 **subagents 分区**：启动时按 `SUBAGENT_SPECS` 播种（builtin 查漏补齐），**已存在的定义不随代码刷新**——用户经管理页的编辑是最终事实（可编辑承诺）。
- 管理页：设置页「墨道·Work → 智能体」分区（唯一挂载点=设置页，见 [设置页](设置页.md)）；`/api/work/subagents` 提供清单。
- 领域插件的 `plugin:agent` 子智能体经宿主解析后合并进同一注册表（见 [领域插件](../concepts/领域插件.md)）。

## 与策划案路径 A 的关系

策划案 4.4 给过两条落地路径：A 技能化（推荐渐进）、B 多智能体注册。实际走了 **B**（`options.agents` + Agent 工具），但每类仍复用路径 A 设想的全部已实现资产（12 技能 + 科研 MCP 工具）。审辨迭代循环（sub-review 打分→回环重做）仍是**待实现**——评审子智能体已可委派，但自动回环未接。
