# 构建打包体系（pack / build / tsconfig）

墨台的编译-构建-打包链路：三份 tsconfig 分管三层源码，build.js 拼接渲染层单文件，pack.js 零下载产出约 362MB 便携目录版并自检冒烟。

## 三配置编译（app/tsconfig*.json）

| 配置 | 覆盖 | 关键选项 | 产物 |
|---|---|---|---|
| `tsconfig.json` | 核心层（main/preload/server/shared/构建工具），strict 全开 | `module:commonjs`、`outDir:"."` 落回原路径（下游零改动）、`noEmitOnError`、**必须显式 exclude**（否则 outDir=. 被默认排除致 TS18003）；exclude 含 src/webapp、src/verify、skills-plugin | main.js / server/*.js 等 |
| `tsconfig.webapp.json` | 前端 webapp 层 | `module:none`（全局脚本模型：主脚本与 work/*.ts 拼接进同一 IIFE 共享作用域，按无模块编译与运行时语义一致）、strict 关闭（体量大无对外类型面）、`outDir:../01` | 01/webapp.js、01/work/*.js |
| `tsconfig.verify.json` | 验证脚本 + skills-plugin/build.ts | 宽松（允许隐式 any），noEmitOnError 仍生效 | verify/*.js |

⚠️ 与 [ts-migration](../sources/ts-migration.md) 的矛盾：迁移说明（2026-09-13）记载前端「有意保持 JS」并列为二期建议；**现已落地 TS 化**（`src/webapp/` + 专属 tsconfig），`01/` 目录是 `src/webapp/` 的同步工作副本。迁移说明中"19 文件"的范围描述已过时。

## 渲染层构建（build.js）

`renderer/index.html` = 三段拼接、**顺序不可调换**：① 主脚本（01/主页面.html + 01/webapp.js）② Work 模块 bundle（01/work/*.js 内联，需读主脚本顶层 const）③ 桌面桥接脚本（注入）。标记 `CS_WORK_MODULES` / `CS_MAIN_SCRIPT` / `CS_DESKTOP_BRIDGE`。⚠️ build 产物勿直接改；⚠️ build.js 打印的是**字符数**，文件大小是 UTF-8 字节数，含中文产物字节数明显更大，不可直接比较（曾据此误判"产物变小"）。

## 打包（pack.js）

- **零下载原则**：不用 electron-packager（默认从 GitHub 下载 Electron zip，本网络不可达会卡死）→ 直接复用本机 `node_modules/electron/dist` 运行时，electron.exe 改名 ChatScience.exe。
- **流程**：第 0 步 tsc 编译（类型不过即中止）→ build.js 构建渲染层 → 复制 Electron 运行时 + main/preload/server 编译产物 + node_modules（排除 electron/typescript/@types）→ rcedit 写 PE 图标与 FileDescription/ProductName（Windows 通知身份依赖此）→ 产物自检（关键文件、require SDK/express、zod 存在）→ 启动冒烟（20 秒内必须写出 runtime.json，随后 taskkill）。
- **产物**：`dist/ChatScience-win32-x64/`（约 362—365MB 目录版绿色便携，非单文件）；**asar 关闭**，`resources/app/` 明文可改，配「重新构建.bat」（只跑 node build.js，包内无 TS 工具链）。选目录版理由：便于后期修改（单文件 exe 解压临时目录无法改）。
- **PACK_SKIP_HEAVY=1**：跳过 Electron 运行时与 node_modules 大体积复制（增量约 35s）；**应用源码总是重拷**保证修复进产物；⚠️ 依赖变动时必须全量。全量重打包保留用户 `resources/app/data/`。
- **运维**：用户数据在 `resources/app/data/`（删之即重置）；分享前必清理 `resources/app/server/qoder.json`（含 PAT 等同账户身份，泄露去 Qoder Integrations 页吊销）；exe 版本信息仍是默认值（待办）。

## 启动与验证闭环（本机硬约定）

- 标准链：`$env:PACK_SKIP_HEAVY="1"; node app/pack.js` → 由 **explorer.exe 代理启动** `dist/ChatScience-win32-x64/ChatScience.exe`（免参数）→ 轮询确认：进程存活 + 端口 8642 监听 + `resources/app/data/boot-marker.log` 出现新的 `lock=true`。
- ⚠️ **explorer 代理是唯一自动化启动路**（2026-09-17 穷尽实测）：run_in_background（进程随任务上下文回收）、cmd /c（安全层拦截）、bat 内 start（静默失效）、WScript.Shell COM（拦截）、Start-Process 即使禁沙箱（派生进程仍被回收）全部失败；explorer 父进程为系统 explorer，完全脱离沙箱进程树。代价：不能传参 → 只能启动免参数打包版 exe（开发模式 `electron .` 带路径参数走不通）。
- ⚠️ 启动前必须先杀旧实例（[Electron桌面层](Electron桌面层.md) 单实例锁会让新实例静默退出）。
