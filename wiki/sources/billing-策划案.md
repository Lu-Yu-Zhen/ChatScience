# 06-订阅预付费板块实现策划案（摘要）

墨台商业化计量与订阅体系的完整设计：双计量模型、个人四档/团队三档、免费用户与签到、充值包与到期规则、功能门禁与技术落地方案。

## 关键结论

1. **实质性零实现**（全代码库检索证实）：无计费 API、无 Token 计量（`chatStream()` 完全不读上游 `usage`，为最大技术缺口）、无积分/会员/签到/充值/门禁/看板。唯一残留是 `01/webapp.js:182,276` 的 i18n 键 `upgrade:'升级 Pro'`（无调用点，按钮从未渲染）。
2. **双计量模型**：Chat 高阶 Token 账户 + Work 积分账户（算力维度，决定能不能跑）× 会员档位（权限维度，决定能用哪些功能）。两条铁律：算力与权限彻底解耦；免费用户有积分即可体验 Work。
3. **档位设计**：个人四档 49/139/299/699 元/月；团队三档 89/199/369 元/月（对标个人档、额度略高、团队共用）。四档均享 Chat 基础模型无限。
4. **权益分批上线**：多项权益依赖待实现能力（迭代、模板、快照、仿真、集群等），批次一用已实现能力（12 技能、6 工具、5 档模型、自定义 API）撑起四档差异。
5. **到期规则**：权益收回 + 余额保留（积分/Token 与会员订阅两条独立生命周期，数据结构必须分离）。
6. **免费用户**：注册赠 200 初始积分（约 200 次基础工作流，先体验价值再遇墙）；每日签到 +100 积分（与套餐积分合并、同有效期、当月清零）。
7. **支付路径**：兑换码（冷启动，零云端）→ 网页支付。
8. **可复用参考**：`agentsview-report/usage-daily.json`（第三方工具产物）提供成熟 Token/成本计量数据形态。

## 前置决策（P0 阻塞项）

法务合规评估（预付费/虚拟额度/退款/发票）、计费定位（本地自律性计量 vs 云端可信账本）、账号体系方案（团队版前置，当前纯本地单机为架构级缺失）。
