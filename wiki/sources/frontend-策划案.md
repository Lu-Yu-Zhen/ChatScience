# 前端板块实现策划案摘要

墨台前端工程层实测策划案：技术栈裁定、模块划分、构建链路、状态管理、前后端通信、i18n、性能与工程化。与 UI 板块的分界——UI 定"长什么样"，本案定"怎么搭、怎么跑、怎么扩"。

## 核心内容

- **技术栈裁定**：策划案原设想 React+Vite+Tauri+Zustand，实测**全部以已实现为准**——Electron 33 + 原生 JS 单文件前端 + 自研状态区 + SSE；React 迁移列为长期演进项。
- **架构全景**：main.ts（窗口/托盘/IPC 白名单/180ms 落盘）→ preload 安全桥 → renderer/index.html（构建产物，主脚本 webapp.js + Work bundle 13 模块 IIFE + 桌面桥接脚本三段拼接）→ Node/Express 后端（127.0.0.1 + Bearer token）。
- **关键决策**：不重写单文件前端（成熟资产，重写风险大于收益）、无前端构建器（本地分发，拼接消除路径复杂度）、验证脚本用 JS 不用 TS（行为安全网）、180ms 防抖 + tmp/rename 原子写。
- **模块体系**：13 个 work 模块数字前缀字典序=执行顺序、共享同一闭包作用域；主脚本 webapp.ts 30 万字符/5717 行为最大技术债。详见 [前端架构](../entities/前端架构.md)。
- **构建链路**：字典序收集 + 首末断言（00-core/90-boot）+ 逐文件 `node --check` 语法门禁 + 函数式 replace（防 KaTeX `$$` 被当替换模式）+ 5 项产物断言。
- **通信与状态**：IPC（交互 <10ms）+ 本地 HTTP（数据，24 字节随机 token）双通道；环回不启用 TLS（决策：威胁模型不支撑，属过度设计）；SSE 8 类事件序列、33ms 节流、客户端断开即中断；UI/会话/运行态三区未显式划分（P0 待办）。
- **性能红线**：禁 base64 重复赋值、列表必带签名守卫、内容更新不触发容器动画、流式必节流；已知环境限制：窗口遮挡时 Electron 冻结 rAF（非缺陷）。
- **验证方法论**（值得固化）：DOM 断言证明不了视觉可见，必须 `elementFromPoint` + 计算样式在真实窗口验证。
- **落地清单**：A 主脚本按域切分（P0）→ B 状态三区 → C esbuild 升级 → D 双模式动态能力清单 → E 工程化（lint/单测/CI）。
