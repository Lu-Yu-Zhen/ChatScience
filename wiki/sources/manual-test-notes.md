# 测试文件夹人工验证记录

> 测试文件夹/ 是 Work 模式人工验收用的工作区夹具与四份手写记录；本页只登记这些记录能证明什么、不能证明什么，不复写其内容。

## 一、资料清单（实测）

- 记录四份：说明.md（265 字节 / 10 行）`测试文件夹/说明.md:1-10`、中文名文件.md（65 字节 / 3 行）`测试文件夹/中文名文件.md:1-3`、智能体验证记录.md（236 字节 / 3 行）`测试文件夹/智能体验证记录.md:1-3`、ui验证.md（7 字节 / 1 行，正文只有两个字）`测试文件夹/ui验证.md:1`。
- 夹具：一个 Python 小脚本 `测试文件夹/demo.py:1-5`、一份三行中文表格数据 `测试文件夹/数据.txt:1-4`、一份 run 结果文本 `测试文件夹/runcode_test.txt:1-2`、一个 8MB 大文件、两个嵌套目录其中一支带 `测试文件夹/子目录B/更深一层/nested.py:1`，另一支为空目录。
- 该簇已在 Raw 登记表内 `wiki/SCHEMA.md:44`，但记录体量远小于 1KB，逐条以字节与行数实测为准。

## 二、这些记录能证明什么

- 智能体曾以该目录为工作区跑通「列文件 → 读说明 → 创建记录 → 读回确认」四步，并把目的、操作与文件数写进记录 `测试文件夹/智能体验证记录.md:1-3`——这正是工作区模式的语义：进程 cwd 切到用户目录、运行脚本仍留沙箱 `app/src/server/sandbox.ts:165-169`。
- 中文文件名与中文内容可读写 `测试文件夹/中文名文件.md:1-3`，其自述用途就是这项测试。
- 一条 run 结果文本按「cwd=… / sum=5050」两行落进工作区 `测试文件夹/runcode_test.txt:1-2`，与 run_code 产物落 cwd 的行为同形 `app/src/server/qoder.ts:427-452`。
- ui验证.md 的单行取值与数据表第三行的名称列同名 `测试文件夹/ui验证.md:1`、`测试文件夹/数据.txt:4`，形态上是「从右栏读回再写下」的核对样本。
- 机器侧把这些文件当作可核验产物记录在案：Write 落盘并做过内容核验、越界写入被明确拒绝、高危命令静态拦截以沙箱验证 18/18 为据 `app/verify/全功能验证报告.md:35-39`；同页末尾把它们与 8MB 夹具一起列为「验证产物，可按需删除」`app/verify/全功能验证报告.md:150`。
- 同一行清单还记下一条容易读漏的口径：代码文本层对单级向上穿越是明文放行、且沙箱页已作披露，被拦的是两级以上 `app/verify/全功能验证报告.md:39`、`app/src/server/policy.ts:121-123`，而工具级文件 API 对任何上级片段一律拒绝 `app/src/server/policy.ts:88-90`。
- 三个手写验证脚本把该目录当固定工作区，因而这批记录可复跑生成 `app/verify/agent-api-verify.js:2`、`app/verify/domain-p2p5p6-verify.js:2`、`app/verify/domain-switch-verify.js:13`；这些脚本在无运行实例时选择 SKIP 而非失败 `app/verify/agent-api-verify.js:9-12`。

## 三、这些记录不能证明什么

- 它们是自述文本，没有断言、没有工具调用记录、没有独立复核，因此不构成通过判据；判据在验证脚本与其汇总里 `app/src/verify/sandbox-verify.ts:214-222`。
- 记录自称目录有 6 个文件 `测试文件夹/智能体验证记录.md:3`，当前实测顶层 8 个文件加 1 个嵌套文件——它是历史快照，不能当目录现状引用。
- 夹具清单也不能只读那份说明：说明只列了 5 个文件与两个子目录 `测试文件夹/说明.md:5-10`，既不含 8MB 大文件，也不含后来新增的三份记录产物。
- ui验证.md 只有一个词，既没写验证目的也没写预期，单独看无法判定验证对象 `测试文件夹/ui验证.md:1`。
- 大文件只是夹具，目录里没有关于读取与写入上限的任何结论；上限判定是代码行为，需由脚本验证 `app/src/server/sandbox.ts:441-448`、`app/src/server/sandbox.ts:457-466`。
- 空子目录只证明能建目录，不证明产物 diff 的限深行为 `app/src/server/sandbox.ts:169`。
- 沙箱不是安全边界这一件事无法由这些记录证明，也正因为如此才有专门的反向用例 `app/src/verify/sandbox-verify.ts:151-158`，见 [沙箱边界](../concepts/sandbox-boundaries.md)。
- 依赖固定本机路径，换机器即失效；验证脚本同样如此，所以页内只给仓库相对路径。

## 四、与契约的张力

- ⚠️ 冲突：契约把 Raw 定义为「仓库既有资料」`AGENTS.md:13`，而该目录目前不在版本控制内（git 的跟踪清单里没有它），页面结论只能在本机复核；Wiki 系统自身的边界规则见 [Wiki 系统](../entities/wiki-system.md)。缓解办法是下一轮把它提交入库，或把这些记录降级为一次性日志。

## 2026-10-05 新造的科研夹具（带地面真值）

第五批验收需要"算得出真值"的数据，于是在同一目录加了两个文件：

- `测试文件夹/实验指标.csv`：2 组（baseline / fusion）× 3 种子 × 5 epoch 共 30 行，真值由 pandas/scipy 预算——epoch5 均值 0.7650 / 0.8666、差值 0.1016、t(4)=38.38、p≈3.0×10⁻⁶、Cohen d≈31.3（`app/verify/全功能验证报告.md:167`）。验收要求模型算出的数字与这组真值逐项一致。
- `测试文件夹/论文片段.md`：故意埋三处缺陷——正文引用 `[chen2023cmf]` 在参考文献表里无对应、统计结论只写 p<0.05 不给效应量、"所有场景都优于基线且不增加推理开销"无证据；论文自查场景要求三处全抓到并给位置与修法（`app/verify/全功能验证报告.md:168`、`:183`）。
- 出图产物落在 `测试文件夹/out/`（`acc_curve*.png`），与报告里"正确出图 vs 编造出图"两张对照图同源（`app/verify/全功能验证报告.md:198-199`）。

这些是**验收数据**，报告在残留清单里说明若要继续复跑请留着，否则可按需删除（`app/verify/全功能验证报告.md:266`）。
