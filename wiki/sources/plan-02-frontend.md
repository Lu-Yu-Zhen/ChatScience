# 02-前端板块实现策划案

> 一句话摘要：前端板块（技术栈、模块划分、构建链路、状态与通信、性能、工程化）的实现策划案，开篇即声明"凡与已实现冲突一律以已实现为准"。

## 这份资料讲什么

Raw 位置 `墨台实现策划案/_src/02-前端.md`（615 行），覆盖墨台桌面客户端的前端工程层：怎么搭、怎么跑、怎么扩；与 UI 板块的分界是"UI 定义长什么样，本板块定义怎么搭"（`墨台实现策划案/_src/02-前端.md:9`）。

资料自带冲突裁定原则（`墨台实现策划案/_src/02-前端.md:13-24`）：框架 React→**原生 JS 单文件**；外壳推荐 Tauri→**Electron 33 已落地**；状态管理 Zustand→**自研状态区 + 快照 + localStorage 回灌**；模块化懒加载→**构建期拼接为单一 IIFE**；通信 WebSocket→**SSE**；虚拟滚动→**未实现**。这一原则正是本簇页面"以源码为准"的依据。

## 章节骨架

- 二·架构总览：Electron 主进程 → preload 安全桥 → 渲染层三脚本（主脚本 + Work bundle + 桌面桥接）→ 本地 Node/Express 后端（`墨台实现策划案/_src/02-前端.md:35-59`）。
- 三·模块划分：Work bundle 模块清单与逐模块体量职责（`墨台实现策划案/_src/02-前端.md:74-94`）；主脚本 webapp 的职责矩阵（`墨台实现策划案/_src/02-前端.md:98-111`）。
- 四·构建链路：三脚本严格顺序拼接、字典序收集 + 顺序断言 + `node --check` 语法门禁 + 5 项产物断言 + 函数式 replace 防 KaTeX `$$`（`墨台实现策划案/_src/02-前端.md:115-159`）。
- 五·状态与通信：UI/会话/运行态三区（部分实现）、IPC 与 HTTP 双通道、`data/state.json` 快照 + `work.json` 分区 + 180ms 防抖原子写、SSE 事件协议、工具授权阻塞弹窗列为待实现（`墨台实现策划案/_src/02-前端.md:162-241`）。
- 七·i18n / 八·性能红线 / 九·工程化：中英词条 diff、Blob URL 头像、签名守卫、动画门控、三配置 tsc 门禁、12 个验证脚本、"DOM 断言≠视觉可见"方法论（`墨台实现策划案/_src/02-前端.md:309-407`）。
- 十/十二·双模式映射与速查总表（`墨台实现策划案/_src/02-前端.md:494-511`）。
