# 06-订阅预付费板块实现策划案

> 一句话摘要：这份策划案规划了积分与 Token 双计量、个人四档与团队三档会员、免费用户与签到、增值充值包，同时给出版本号级的关键结论——该板块在代码里实质零实现。

## 关键结论：完全零实现

案文开篇即标为【关键结论】：对全代码库（排除 node_modules 与 dist）按 积分/签到/充值/会员/订阅/付费/credits/points/pricing/billing/quota/tier/plan/membership/subscription/checkin 系统检索后，判定"订阅付费体系实质上零实现，仅有 1 处孤立字符串残留"（`墨台实现策划案/_src/06-订阅预付费.md:9-11`）。逐行核对表里最硬的一条是 Token 计量：`chatStream()` 只解析 `choices[].delta`，完全不读取上游 `usage` 字段，全库检索 `prompt_tokens` / `completion_tokens` / `usage_metadata` 零命中（`墨台实现策划案/_src/06-订阅预付费.md:17`）。功能门禁 Feature Flag 一栏为"无"（`墨台实现策划案/_src/06-订阅预付费.md:24`）。

因此案文推论：本板块无历史包袱、可全新设计，但也意味着工作量最大（`墨台实现策划案/_src/06-订阅预付费.md:27`）。

## 双计量模型与不变式

设计核心是两条账户线：Chat 高阶模型走 Token 账户，Work 运行走积分；会员档位（个人四档 / 团队三档）决定功能权限（`墨台实现策划案/_src/06-订阅预付费.md:60-78`）。第一条设计原则被写成加粗不变式——**算力与权限彻底解耦**：积分/Token 余额决定"能不能跑"，会员档位决定"能用哪些高级功能"，二者互不占用（`墨台实现策划案/_src/06-订阅预付费.md:78`）。计量明细见 `墨台实现策划案/_src/06-订阅预付费.md:81-85`（基础模型无限畅用、高阶模型按 Token 计量）。积分阶梯计价与 Token 计量实现方案两处都标了【待实现 — 关键技术缺口】（`墨台实现策划案/_src/06-订阅预付费.md:91`、`:119`）。

## 档位与批次规划

个人四档权益表在 `墨台实现策划案/_src/06-订阅预付费.md:146-161`，通用权益递进在 `:161-169`；与实现状态的依赖核对把每条权益标成 已实现 / 部分实现 / 待实现，并给出"批次一 · 计费地基"用已实现能力撑起四档差异（`:170-205`）。团队三档在 `:212-225`，其前置依赖明写"团队侧能力完全为零实现"（`:225-227`）。免费用户边界、签到机制（含待补充的防刷设计）与 200 初始积分设计在 `:246-276`，增值充值包与到期规则在 `:276-290`。
