# 墨台 · 后端板块实现策划案

## 一、板块定位与冲突处理原则

### 1.1 板块范围

本板块覆盖墨台的**本地后端服务层**：进程与启动架构、HTTP API 面、数据持久化、AI 上游链路、知识库检索、安全与沙箱、打包分发、验证体系、运维与日志。

### 1.2 冲突处理原则

凡策划案（第 5 章 后端设计规划）与已实现内容冲突，**一律以已实现为准**：

| 冲突项 | 策划案原始表述 | 已实现实际（以此为基准） | 裁定 |
|---|---|---|---|
| 后端语言/运行时 | Node.js 承载 SDK，或 Rust 外壳 + Node 运行时混合方案 | **纯 Node.js（TypeScript）+ Express**，随 Electron 内置 Node 20 运行 | 以 Node/TS 为准，Rust 混合方案不采纳 |
| 本地数据库 | **SQLite 保存元数据与消息**，文件系统保存文献/数据/快照 | **JSON 文件**持久化（`state.json` / `work.json`），**无 SQLite** | 以 JSON 为准；SQLite 列为待实现演进项 |
| 服务模块划分 | 统一网关、Chat 会话服务、Work 运行时、会话与存储、MCP/插件管理、知识库与数据库、计费与权限（**7 模块**） | **按域拆分的 Express 路由 + 服务模块**（index/routes/qoder/sandbox/store/notes/kb/ai/research/policy/proc/sse，**12 模块**） | 以已实现模块拆分为准；策划案的"统一网关"由 Express 应用与鉴权中间件承担 |
| 知识库检索 | **向量化 + 检索**（文档解析、分块、向量化、检索） | **BM25 词法检索**（中文 bigram 分词），**无向量库** | 以 BM25 为准（已实现且已明确声明为能力边界）；向量检索列为待实现 |
| 计费与权限服务 | 独立模块（积分账户、Token 账户、Feature Flag 门禁） | **完全零实现** | 列为待实现（详见订阅预付费板块） |
| 团队服务 | 团队知识库、成员权限、审计、用量看板 | **零实现**（仅单人本地） | 列为待实现 |
| 云同步 | 云端承担可选同步、备份、团队协作 | **零实现**（本地优先，无云端） | 列为待实现 |
| 会话存储 | SQLite + external session-storage | JSON + 会话快照 | 以已实现为准 |

### 1.3 状态标记约定

- **【已实现】** / **【部分实现】** / **【待实现】** — 同前两个板块。

## 二、进程与启动架构

### 2.1 双进程模型【已实现】

```
┌────────────────────────────────────────────────────────┐
│  Electron 主进程（main.ts）                             │
│  · BrowserWindow（主窗 1320×880 / 子窗 1080×760）        │
│  · 托盘 + 全局快捷键 + 单实例锁                          │
│  · 状态快照落盘（180ms 防抖 + 原子写）                    │
│  · IPC 白名单                                            │
│  · fork 后端子进程（Electron 内置 Node 20）              │
└────────────────────┬───────────────────────────────────┘
                     │ 127.0.0.1:PORT + Bearer token
┌────────────────────▼───────────────────────────────────┐
│  Node/Express 后端（server/index.ts）                    │
│  · 仅绑定 127.0.0.1                                     │
│  · 随机 24 字节 token 鉴权（无 token → 401）              │
│  · 端口候选回退（6 个）                                   │
│  · runtime.json 记录实际端口与 token                      │
└────────────────────────────────────────────────────────┘
```

### 2.2 启动链路【已实现】

| 环节 | 实现 |
|---|---|
| 后端进程 | 由 Electron 主进程 fork，使用 Electron 内置 Node（非系统 Node） |
| 端口候选 | `PORT_CANDIDATES = [8642, 17462, 27511, 38123, 2917, 3218]` |
| 端口回退 | `tryListen` 递归尝试；`EADDRINUSE` 自动试下一个（曾因 3218 触发 Windows EACCES 而改造为候选回退） |
| 鉴权 | 每次启动生成 `crypto.randomBytes(24).toString('hex')` 随机 token |
| 鉴权校验 | `if (auth !== 'Bearer ' + token)` → 401 |
| 绑定地址 | 仅 `127.0.0.1`（不对局域网暴露） |
| 运行时信息 | 写入 `runtime.json`（实际端口 + token），供验证脚本与调试工具读取 |
| 单实例锁 | `requestSingleInstanceLock` + `second-instance` 唤起已有窗口 |
| 窗口显示兜底 | `ready-to-show` 事件可能先于监听触发 → 3 秒兜底 `win.show()` |
| 启动冒烟 | 打包产物自检时拉起 exe，**20 秒内必须写出 `runtime.json`**，随后 `taskkill` |

### 2.3 前后端职责切分【已实现】

| 层 | 职责 | 明确不做 |
|---|---|---|
| 前端 | 渲染、配置与操作、日志与结果预览、用户干预指令（暂停/重跑/改参/终止）下发 | **不承载任何智能体推理逻辑** |
| 后端 | 全部执行与调度、沙箱、SDK 运行时、存储、AI 代理 | 不做窗口管理（由主进程负责） |

## 四、数据持久化

### 4.1 双文件分区模型【已实现】

| 文件 | 内容 | 写入方 |
|---|---|---|
| `data/state.json` | **前端快照**（会话、项目、模型、UI 偏好，含轨迹剥离规则） | 主进程（180ms 防抖差量检测） |
| `data/work.json` | **工作数据**（智能体定义 / 技能开关 / MCP 服务器 / 沙箱策略 / 模型工具支持 / 运行历史 / 播种标志） | 后端（分区串行化 store） |
| `data/runtime.json` | 运行时信息（实际端口、token） | 主进程 |
| `data/app.log` / `server.log` | 应用与后端日志 | 各自进程 |

**设计要点【已实现】**：两文件**物理隔离**，是"双模式分离、故障互不影响"原则在存储层的落地。

### 4.2 写入机制【已实现】

| 机制 | 实现 |
|---|---|
| **原子写** | tmp + rename（杜绝半写状态损坏） |
| **差量检测防抖** | 180ms 周期比对状态差异，无差异不写盘 |
| **分区串行化 store** | `store.ts` 用 promise chain 保证读-改-写不交错；分区：`agents` / `skills` / `mcpServers` / `sandboxPolicy` / `modelToolSupport` / `runHistory` / `seeded` |
| **种子增量合并** | 内置智能体按 **id 增量合并**（每次启动执行，无变化不写盘）——修复了"改名不生效"问题（原 `seeded` 标志会拦住种子逻辑） |
| **大字段剥离** | 快照同步剥离 `data` / `argsRaw`；`result` / `reasoning` 截断 2048 字符；`SNAP_TRIM_BYTES = 6MB` |

### 4.3 遗留问题【部分实现】

| 问题 | 现象 | 影响 |
|---|---|---|
| 状态落盘延迟 | 180ms 轮询差量，AI 流式输出完成瞬间的最终文本可能延迟一个周期落盘（切换对话会立即触发保存） | 极端情况下异常退出丢最后一帧 |
| 二进制文件不落盘 | `file.data`（附件二进制）仅存内存，不落盘（隐私与体积考量） | 重启后知识库文件需重新上传 |

**待实现**：把关键状态改为事件驱动立即落盘（保留防抖作为兜底），或引入 WAL 式增量日志。

### 4.4 沙箱目录布局【已实现】

```
data/sandbox/<scope>/
├── work/          ← Agent 可见写区（SDK cwd 与 run_code 进程 cwd 指向此处）
├── out/           ← 产物输出区（Agent 写在这里的产物被回传前端）
├── .hooks/        ← 断网等注入钩子
└── .meta.json     ← 沙箱元数据（scope、创建时间、策略快照等）
```

**scope 语义【已实现】**：
- `global` — 全局共享沙箱
- `conv-<id>` — 会话独立沙箱

**工作区模式差异【已实现】**：会话绑定本地工作区后，SDK 的 `options.cwd` 与 `run_code` 的**进程 cwd 同步切换**到该工作区；`canUseTool` 的写入守卫根同步切换；但 `_run_*.py` 等运行脚本仍写沙箱目录，**不污染用户工作区**。

### 4.5 数据库演进方案【待实现】

策划案要求 SQLite 保存元数据与消息。当前 JSON 方案在以下场景会碰到瓶颈：

| 瓶颈 | 触发条件 |
|---|---|
| 全文件读写 | 会话数 > 数千，或单会话消息 > 数万条 |
| 无索引查询 | 按时间/关键词检索历史消息 |
| 无事务 | 多分区并发写入 |

**演进方案（渐进式，非推倒重来）**：

| 步 | 动作 |
|---|---|
| 1 | 抽象存储接口（`Store` 接口已存在，需扩展为泛型 KV + 集合接口） |
| 2 | 引入 SQLite（`better-sqlite3`，同步 API 契合当前代码风格）存**消息与会话元数据** |
| 3 | 保留 JSON 存**配置类数据**（智能体定义、沙箱策略等低频小数据）——避免过度工程 |
| 4 | 提供一次性迁移脚本（读 JSON → 写 SQLite），并在启动时校验 |
| 5 | 文件系统继续负责文献/数据/仿真文件/快照（不适合入库的大对象） |

### 5.2 实测指标【已实现】

| 指标 | 值 | 说明 |
|---|---|---|
| 10 轮对话成功率 | **10/10（100%）** | DeepSeek-V4 论文全文注入 |
| 关键词校验 | **10/10** | 含标题、参数量、上下文长度、多轮回指 |
| 平均首字延迟 TTFT | **16,216 ms** | **注入 17.2 万字符上下文下的上游时延**，非本地同步延迟 |
| 平均总时延 | 36,417 ms | 同上 |
| 平均输出长度 | 4,002 字符 | — |
| 数学公式（`$$` LaTeX） | 通过 | 第 5 轮 |
| 代码块渲染 | 通过 | 第 6 轮 |
| 多轮连贯性（回指） | 通过 | 第 4、8 轮 |
| 中断恢复 | 正常 | SSE 连接正常关闭，无悬挂流 |

**【重要说明】** TTFT 16.2s 是**上游厂商在超长上下文下的真实时延**，不是本地链路缺陷。本地同步延迟（交互类操作）为 <10ms 量级。

|---|---|

## 六、知识库服务

### 6.1 已实现（BM25 词法检索）【已实现】

| 项 | 实现 |
|---|---|
| 算法 | **纯词法 BM25**（`K1 = 1.5`, `B = 0.75`），**无向量语义** |
| 分词 | **中文 bigram 分词** |
| 分块 | `CHUNK_CHARS = 600`，`CHUNK_OVERLAP = 80`，`MAX_TEXT = 900000` |
| 索引 | 前端推送文本 → 索引落盘 |
| 检索 | `kb_search` 工具（in-process MCP），返回带 score |
| Agent 集成 | Agent 会话内 `kb_search` **真实命中**（已验证） |
| 排序质量 | 验证通过：注意力文档排前、无关查询零误召回 |
| 无索引时 | 返回引导文案 |

### 6.2 能力边界（已声明）【已实现】

| 边界 | 说明 |
|---|---|
| **非语义检索** | 同义改述会漏召回；返回 score 供模型自行判断 |

### 6.3 向量检索升级方案【待实现】

策划案要求"文档解析、分块、向量化与检索"，支持文献/实验记录/表格/稿件多类型，按项目与个人/团队空间隔离，给出容量配额。

**升级方案（混合检索架构）**：

| 层 | 技术选型 | 理由 |
|---|---|---|
| 分块 | 保留现有 600 字符 / 80 重叠，**增加语义分块**（按标题层级与段落边界切分） | 提升检索粒度合理性 |
| 词法检索 | 保留 BM25 | 精确术语、公式、专有名词命中可靠 |
| **向量检索** | 本地嵌入模型（如 `bge-m3` / `text-embedding-v3`）→ 向量存 SQLite（`sqlite-vec` 扩展）或独立的轻量向量索引文件 | 本地优先原则，不依赖云端；`bge-m3` 中文与多语言表现好 |
| 混合排序 | **RRF（Reciprocal Rank Fusion）** 融合 BM25 与向量两路结果 | 无需调参，鲁棒 |
| 重排（可选） | 交叉编码器重排 top-K | 精度提升，成本可控 |
| 多类型解析 | 复用已实现：PDF（pdf.js 前端 + 后端抽取）、DOCX（mammoth）、XLSX（xlsx）、Markdown/HTML | 已有基础 |
| 空间隔离 | 索引文件按 `scope`（个人 / 项目 / 团队）分目录 | 与沙箱 scope 模型一致 |

## 七、安全与沙箱

### 7.1 纵深防御体系【已实现】

产品采用**多层防御 + 诚实的边界声明**策略（而非宣称不可绕过的隔离）：

| 层 | 机制 | 强制力 |
|---|---|---|
| 网络层 | 仅绑定 `127.0.0.1`（不暴露局域网） | **强** |
| 鉴权层 | 每次启动随机 24 字节 token，Bearer 校验，无 token → 401 | **强** |
| 进程隔离 | `contextIsolation: true` + `sandbox` + IPC 白名单 | **强** |
| 执行层 | `shell: false` + argv 数组（不经 shell 拼接） | **强（唯一不可绕过层）** |
| 路径层 | `assertInside` + `sanitizeRelPath`，防 junction/symlink 逃逸；写入守卫根随工作区切换 | **强** |

| 命令拦截 | `canUseTool` + policy 静态扫描 **16 类危险模式** | **弱（可绕过）** |
| 资源限制 | 超时强杀、并发信号量、输出上限、文件大小上限 | **中** |

### 8.3 打包期专属故障（重要经验）【已实现】

**症状**：打包版 Work 模式全部请求失败、选工作区无任何反应。

**根因**：**打包版 server 从未启动**。`qoder.ts` 顶部静态 `require('@qodercn-ai/qodercn-agent-sdk')`，而 SDK 是**纯 ESM 包**——系统 Node 24 的 `require(esm)` 能加载（开发环境正常），但 **Electron 33 内置 Node 20 不支持**，`ERR_REQUIRE_ESM` 使 server 模块加载失败。

**后果链**：所有 `/api/*` 无人监听 → `onPort` 不触发 → 界面静态可开但一切后端能力为空。

**修复**：改为动态 `import()` **惰性加载**（`loadSdk()`，进程内缓存一次；CJS 中动态 import 在 Electron 内置 Node 20 可用），`runWorkTurn` / `ping` / `buildScienceServer` 改为 await 注入。

**叠加陷阱（TypeScript 特有）**：tsc 在 CommonJS 输出中会把**一切** `import()`——包括变量指示符——统一改写为 `require()` 包装，**重新引入** `ERR_REQUIRE_ESM`。

**解法（已实测有效）**：用 **Function 间接层**构造真实 `import()`，编译器无法识别、原样保留：

```ts
const dynamicImport = new Function('specifier', 'return import(specifier);');
sdkPromise = dynamicImport(SDK_PACKAGE_SPEC).then(m => m.default || m);
```

已实测：编译产物中确认**无任何对 SDK 的静态 require**；SDK 经该通道加载成功（`query` / `tool` / `createSdkMcpServer` / `accessToken` 均为 function）。

本章把前文的「待实现 / 部分实现」项收拢为可施工清单：**改哪个文件、新增哪组端点、如何验收**。按优先级分五组。

### 13.2 A 组：AI 链路缺陷修复（P0）

| # | 缺陷 | 现象 | 修改方向 |
|---|---|---|---|
| A1 | **Chat 深度思考开关无效** | UI 有开关但请求中未生效 | 核对开关值到请求体的映射链路，确认是否被 L1 层默认值覆盖；补请求体快照断言 |
| A2 | **`runtimes?force=1` 不生效** | 强制重拉运行时参数被忽略 | 核对查询参数解析与缓存判定的先后顺序 |
| A3 | **错误文案缺括号** | 报错信息格式残缺，影响用户理解 | 统一错误文案模板，补严谨的括号包裹与占位符替换校验 |
| A4 | **上下文裁剪缺失** | 长会话无裁剪策略，存在超出模型窗口风险 | 新增裁剪策略：按 Token 预算保留最近 N 轮 + 系统提示与关键上下文；裁剪需可见（前端提示） |
| A5 | **思考开关修复** | 同 A1（属已识别缺陷，需专项验证） | — |

**验收方法**：A1/A2 用请求体断言验证参数确实到达后端；A4 用超长会话实测不报窗口错误且关键上下文保留。

### 13.3 B 组：持久化与落盘补齐（P0）

| # | 待补项 | 现状 | 修改方向 |
|---|---|---|---|
| B1 | 落盘延迟 | 180ms 防抖导致崩溃可能丢最近写入 | 关键操作（会话创建、配置变更、笔记保存）改为**立即落盘**，非关键仍走防抖 |
| B2 | 二进制不落盘 | 新增二进制不写入 state | 二进制（头像、附件）独立目录存储 + 索引写入 state，启动时校验一致性 |
| B3 | 原子写可观测 | 原子写已实现但无失败上报 | 原子写失败时记录错误并重试一次，仍失败则告警 |
| B4 | SQLite 演进评估 | 双文件 JSON 分区 | 当单分区记录数超阈值或出现查询需求（见 E 组）时，评估迁移 SQLite；**当前不迁移**，先做接口抽象以便未来替换 |

**验收方法**：强制杀进程后重启，确认已确认的关键操作不丢失；二进制资源完整可读。

### 13.4 C 组：安全纵深加固（P1）

现状已有 9 层纵深防御（回环绑定、token 鉴权、进程隔离、`shell:false`、路径守卫、16 类危险模式拦截、超时强杀、并发信号量、环形采集）。需补：

| # | 待补项 | 修改方向 |
|---|---|---|
| C1 | **拦截可绕过** | 16 类 `DANGER_PATTERNS` 为模式匹配，存在绕过可能。改为**白名单优先**：默认拒绝未知命令形态，仅放行显式允许的形态；模式匹配退为辅助 |
| C2 | Job Object | 用 Windows Job Object 约束沙箱子进程资源上限与连带终止（当前依赖超时强杀） |
| C3 | 内存统计 | 采集沙箱进程内存占用，超阈值告警或中止 |
| C4 | 强制断网 | 现状为声明式（仅提示），需落地为真实的网络命名空间/防火墙级隔离 |
| C5 | 审计服务 | 危险操作全记录（谁、何时、对什么、结果），独立审计日志不可篡改 |

**验收方法**：C1 用绕过用例集（编码变形、管道拼接、别名替换）做红队测试；C2/C3 用失控脚本验证资源约束生效。

### 13.5 D 组：知识库向量化升级（P1）

**现状**：BM25 词法检索（K1=1.5 / B=0.75）、中文 bigram 分词、600/80 分块、Agent 集成完备，但**非语义**——同义改写、跨语言查询召回差。

| # | 动作 | 说明 |
|---|---|---|
| D1 | 引入向量检索 | 新增 embedding 通道，与 BM25 并行 |
| D2 | RRF 混合排序 | 用 Reciprocal Rank Fusion 融合词法与向量两路结果，避免单一策略偏置 |
| D3 | 增量索引 | 文档变更时增量更新向量，不全量重建 |
| D4 | 容量配额 | 知识库容量上限与超限提示（与订阅板块权益联动） |
| D5 | 降级路径 | 向量服务不可用时自动回落纯 BM25，**不得中断检索** |

**验收方法**：构造同义改写与跨语言查询集，对比混合检索与纯 BM25 的召回率提升。
