### 1.3 【关键风险】四套品牌名称并存

项目内**同时存在四个互不一致的品牌标识**：

| 来源 | 品牌名 | 视觉风格 | 接入状态 |
|---|---|---|---|
| 产品策划案 | **墨台**（Work 模式智能体系统：**墨道**） | 东方水墨美学 | 文本规划 |
| 已接入应用图标 | ChatScience（粉蓝气泡） | 粉色渐变 SaaS | **已接入产品**（窗口/托盘/exe 图标） |
| InkForge 品牌提案 | **墨砺 / InkForge** | 玄黑 + 石青 + 丹朱（水墨 × 科技） | 未接入 |
| 既有宣传海报 | **CHATSCIENCE** | 宝蓝科学风 | 宣传物料 |

**这是宣传板块的最高优先级问题**——在品牌名与视觉未统一前，任何投放都会造成认知混乱与资产浪费。

**裁定建议**：

| 项 | 建议 | 理由 |
|---|---|---|
| 品牌名 | **以「墨台 / 墨道」为唯一产品名** | 策划案为最新且最完整的产品规划；"墨台/墨道"与已实现的墨色 UI 基调、与"墨"的产品基因完全自洽 |
| 英文名 | **保留 ChatScience 作为英文名/工程代号** | 代码、包名（`chatscience-desktop`）、目录、技能命名（`chatscience-skills`）已全面使用，改名成本高且无必要；可对外表述为"墨台 ChatScience" |
| **InkForge 提案的处置** | **作为视觉基因库（配色/辅助图形）采纳，但放弃其命名** | 其色卡（玄黑/石青/丹朱）与已实现 UI 的中性墨色体系**天然契合**；但"墨砺"作为产品名与"墨台"直接冲突 |
| 应用图标 | **重做** | 粉蓝气泡与墨色 UI、水墨品牌完全脱节 |

### 2.1 品牌架构建议

```
主品牌：墨台（MoTai）
  ├─ 英文名/工程代号：ChatScience
  ├─ 核心智能体系统：墨道（对应 Work 模式）

| 来源 | 表述 |

### 3.2 Slogan 体系建议【待实现】

策划案规划了三组场景化 Slogan，本身**质量较高，建议保留**，仅在措辞上与已实现能力对齐：

| 场景 | Slogan | 备注 |
|---|---|---|
| **主传播语（推荐）** | **「轻对话用 Chat，深科研交给墨道」** | 差异对比型，与已实现的"双模式分离"核心架构完全对应，最好记、最能表达独特价值 |
| 主品牌主张（长句） | 「让科研从重复劳动中解放，把精力还给思考」 | 适合落地页首屏、品牌片旁白 |
| 传播短句 | 「把重复劳动交给 AI，把思考留给研究者」 | 海报主视觉（已在用，沿用） |
| 价值主张型 | 「墨台：Chat 无限畅聊，墨道多智能体跑通科研全流程」 | 详细介绍场景 |
| 团队协作型 | 「个人知识库加团队协作，一站式科研 AI 工作台」 | 团队版推广（**注意：团队能力尚未实现，需在团队版上线后启用**） |
| 品牌品性（四字） | 「格物砺知」 | 可与"墨台"组合使用（如"墨台 · 格物砺知"），用于品牌调性表达 |

**主 Slogan 选择建议**：**「轻对话用 Chat，深科研交给墨道」**。理由：
1. 直接命中双模式分离这一**唯一性架构差异**；
2. 已实现（Chat 链路与 Work 链路均已完整可用）；
3. 对仗工整，适合做视觉主标。

### 3.3 品牌主张的合规约束【重要】

策划案明确要求"坚持科研辅助工具定位，不承诺自动产出论文或保证实验结论，避免'替代科研人员'等夸大表述"。

**基于项目实测的表述纪律**（结合 Agent 板块的能力边界）：

| 禁止表述 | 原因 | 建议表述 |
|---|---|---|
| "自动写论文" / "一键出论文" | 能力边界：Agent 单次运行至 `maxTurns` 结束，无迭代循环 | "辅助论文撰写与审校" |
| "完全隔离的沙箱" | 能力边界：`canUseTool` 拦截可被绕过 | "沙箱内执行代码，危险操作静态拦截 + 独立进程隔离" |
| "保证结论正确" | 能力边界：无评审智能体校验 | "全流程轨迹可追溯，结果可复现" |
| "断网运行绝对安全" | 能力边界：声明式断网不可强制 | "可声明断网运行" |
| "全部无限" | 计费口径：Chat 基础模型无限、高阶耗 Token、Work 耗积分 | 明确区分三类额度（见订阅板块） |
| "替代科研人员" | 定位错误 | "把重复劳动交给 AI，把思考留给研究者" |
| "智能体自主调度七类子智能体" | **七类子智能体为待实现** | "内置科研技能与工具，覆盖文献到论文全流程" |

**核心纪律**：**宣传口径必须与《Agent 系统设计》板块第九章的能力边界表严格一致**，不得宣称待实现能力。

| 用户类型 | 典型角色 | 核心痛点 | 墨台对应能力（**已实现部分**） |

### 6.3 转化路径

```
内容触达
  → 下载客户端

  → 引导在 Work 跑通第一个工作流  ← 已实现，是价值的"分水岭"

**关键设计洞察**：Chat 模式的即时价值（零配置、直接可用）是**最优的获客入口**；Work 模式跑通第一个工作流（如"检索并精读一篇 arXiv 论文"，这是已实现的黄金路径）是**转化的关键拐点**。因此内容投放应重点演示"从 Chat 一句话到 Work 全流程"的平滑过渡。

## 七、宣传合规与风险规避

### 7.1 合规红线【已实现，来自策划案 + 项目实测】

| # | 红线 | 具体要求 |
|---|---|---|
| 1 | **科研辅助工具定位** | 不承诺自动产出论文，不保证实验结论，避免"替代科研人员"等夸大表述 |

### 11.8 施工顺序建议

```
A 组（品牌决策，阻塞项）→ B 组（资产重制）→ C 组（物料产出）→ E 组（合规核对）→ 发布
                                    ↘ D 组（渠道内容，个人版可并行启动）
                                                                          ↘ F 组（公测后）
```

**关键纪律**：

1. **A 组不做完不生产任何物料** —— 否则可能全部返工。
2. **物料宣称必须能追溯到验证记录** —— 这是本项目最需要警惕的红线，因为产品存在大量"策划案说了但代码没做"的能力。
3. **个人版预热不必等计费** —— 不要因为后端能力未就绪而推迟全部宣传工作。
